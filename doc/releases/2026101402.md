# ZIMA-CAD 2026101402 — Windows

## Changes

Ordinary selection of a modeling feature keeps its Tree row collapsed and its
icon colors stable. Selecting its wire in the View selects the owning feature,
while direct selection of a Sketch child and double-click inspection remain
available. The actual two Extrusions in the user's `02.prtz` pass this check.

Ordinary Part calculations and Assembly cuts defer per-face area integration.
Explicit Measurement and other scalar-analysis commands use exact persisted
native geometry when requested, without replaying modeling history or adding
Undo transactions. Required original sources remain inside the native file.
Subtract histories retain bounded exact prefix references for correct warm
edits. Saving avoids repeated large JSON/string copies and preserves full
temporary-file reload validation.

The Assembly insertion marker now controls one ordered history including
immediate components, Sketches, cuts and construction objects. Moving it selects
cached input geometry, keeps later Tree rows inactive and performs no mate or
OCCT regeneration. Middle insertion, Undo/Redo, native reopening and exact nested
activation retain their ownership. Measurement follows the active displayed
input while passive occurrences retain their complete calculated result.

Assembly documents use JSON 48 / INI 36 with required typed history and cursor
fields. Both start Assembly templates are regenerated. There is no legacy
Assembly migration path. The shared placement solver/panel, native Part schema,
geometry precision and pinned OCCT 8.0.0 remain unchanged.

## Finite Windows verification

Twenty-nine selected native/GUI contracts pass after repairing and rerunning
the initially rejected cases. Coverage includes cache encoding, exact requested
face areas, native Assembly format/metadata, mixed history, ordering/dependencies,
profile references, construction/3D Curve, copies, nested ownership, measurement,
feature selection, Shell, Fillet/Chamfer, FORM, native save/reopen and New Document
creation from both regenerated Assembly templates. Five-language catalog and
coverage validation passes. These checks do not claim an exhaustive Sketcher
dimension/drag matrix; no Sketcher solver algorithm is changed.

All 20 affected native factory assets are calculated, saved and reopened with
the changed implementation. Their authored histories and reference definitions
remain equal, and complete calculated packets roundtrip. The refreshed factory
`ZE-TEXT.symz` is committed from its separate generated copy; the user's edited
working file, settings and original `02.prtz` are preserved.

Representative `02.prtz` samples on the same Windows host:

| Operation | Baseline | Follow-up |
| --- | ---: | ---: |
| Save unchanged original calculated data, including validation | 109.1 s | 80.5 s |
| Cold last Subtract | 68.1 s | 56.6 s |
| Cold last Add | 76.8 s | 63.0 s |
| Changed last Subtract / restore with complete warm cache | — | 21.5 / 22.7 s |

Original-data saving preserves exact bytes and full definition/packet digests.
Cold geometry/reference digests match after excluding only the intentionally
changed analysis representation. Warm Subtract restores the complete packet
exactly. Separately, saving freshly calculated deferred-analysis data takes
89.2 s and produces 857,069,090 bytes, with exact independent reopen validation.
These finite samples are not universal speedup guarantees.

The eager Add baseline and follow-up warm probe both exhibit a pre-existing
three-p-curve archive variation after restoring draft angle. A non-destructive
Boolean experiment was removed; no warm Add timing is accepted from those failed
probes. Remaining edge publication/archive/save-validation cost and native Linux
execution gaps are explicit in the linked records.
