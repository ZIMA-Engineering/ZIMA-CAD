# Windows build 2026101201

## Browser rendering and window lifecycle

The integrated browser could display a black content area because the Windows
Qt Quick default graphics API differed from the OpenGL API used by the CAD
widgets in the same main window. The desktop now selects OpenGL for Qt Quick
before constructing QApplication. Hardware acceleration, the CAD surface
format, geometry precision and the shared Windows/Linux implementation remain
unchanged. No kernel, model format or container-placement contract changed.

The browser regression harness now creates a CAD OpenGL context before opening
a real local HTTP page and checks its rendered colors. Its diagnostic
`--default-graphics-api` mode reproduces the former mixed-API failure; the
ordinary OpenGL mode passes. A data-URL fixture is unsuitable because browser
navigation deliberately rejects that scheme.

The main-window regression checks actual native-window pixels, Light/Dark/Light,
resizing, repeated CAD/browser switches, multiple tabs, settings Cancel and
return to the saved CAD document. It observes native surface, window-ID and
Hide events when opening the first browser in an empty application and beside
an existing CAD document. Opening a browser must retain the same visible native
main window. Offscreen runs explicitly skip native-screen pixel verification.

## Global Settings

The initial width fits the translated tab strip, with a baseline of 820 logical
pixels and the existing shared internal-window bounds. Manual resizing and
System Setup retain their existing behavior. All five languages are checked
for tab-strip fit and main-window bounds. This change adds no user-visible
strings or translation keys; existing catalogs require coverage and placeholder
validation with the GUI checks.

## Acceptance

Eight focused Windows suites passed in 68.21 seconds: bookmarks, the browser
harness, imported-body interaction, five-language translation/source coverage,
viewer picking, Axis Up To, native browser-window composition and new-document
templates/options. The negative default-graphics-API harness failed its pixel
check; the same fixture with OpenGL passed. The complete tab strip fit in the
820-pixel settings window for Czech, English, German, French and Russian (the
Russian strip required 783 pixels). First browser loading, native window
identity and repeated CAD/browser switches passed without Hide or native
surface recreation events.

The committed-source candidate and signed archive passed dependency closure,
path/collision/member-length checks, CRC, SHA-256, inventory validation and
native smoke. The saved/reopened Part has volume 6000 mm3; PDF/JPEG export,
GUI rendering and loading all 21 committed factory native assets passed without
changing their hashes. The reusable build's old source was verified byte for
byte against its recorded Git commit before the new source was exported.
Ninja records 748 valid dependencies for the main workspace object.

The signed runtime passed five isolated GUI scenarios in 54.86 seconds:
browser composition/window lifecycle, STEP source tabs, Axis Up To,
five-language new-document templates/options and imported-body interaction.
The browser harness also passed with only packaged dependencies. Production
bootstrap reports installed version 2026101201 and `trusted: true`; immutable
runtime and source inventories remained unchanged after acceptance.

An accidentally unisolated full startup diagnostic reached a Save Copy
calculated-history fingerprint assertion. The exact same assertion reproduces
in the previous signed 2026101108 runtime. It is an existing broader-sequence
failure, remains outside this browser display fix, and is not counted as a
passing full startup suite. The correctly isolated affected suites pass.
