# Windows 2026102801 — background analysis and reversible history reuse

This Windows release candidate follows `2026102702` with conservative
performance and geometry corrections measured on an isolated copy of a large
automotive Skeleton. Protected source data is not included in the repository or
package. The experimental semantic multi-Boolean evaluator remains disabled.

## User-visible changes

- Exact mass, area, centroid and inertia integration no longer extends ordinary
  Part or Assembly regeneration when those values are only outputs. After the
  model becomes idle, the GUI completes pending physical analysis on a private
  low-priority worker and publishes it only if document identity, revision and
  generation still match. Save and explicit inspection remain exact fallbacks.
- Saved Body Properties rows request synchronous analysis only when their
  centroid origin is an actual input to later geometry. Otherwise they are
  completed with the rest of the physical analysis outside the command's
  geometry-critical path.
- Opening Body Properties publishes its exact history-input scene directly,
  without first building and uploading a complete scene that is immediately
  discarded.
- Returning to a previously visited parameter value, including Undo/Redo,
  reuses its validated in-memory native continuation frame. This avoids
  rebuilding and reserializing equivalent OCCT topology and preserves the exact
  native/reference packet.
- A Thin profile now accepts the valid limiting case where an inward offset is
  exactly equal to a tangent corner radius and the arc collapses to a sharp
  vertex. Connectedness, closure and B-Rep validity are still required; invalid
  and over-inradius offsets remain rejected.
- Activated Skeleton Part feature and Sketch rows retain their exact occurrence
  path in an Assembly, restoring the ordinary View context-menu route for that
  active occurrence.

## Representative measurements

The protected 32-operation Skeleton was tested only through an isolated local
copy. Its original SHA-256 remained unchanged.

- Native load was approximately 7.4 seconds.
- Cold explicit regeneration completed in approximately 68.9 seconds after
  aggregate physical integration was removed from the geometry-critical path.
- Regeneration followed by exact Save analysis completed in approximately
  101.3 seconds; roughly 30 seconds of exact integration is now outside `OK`.
- Editing the final Thin operation from 5.0 mm to 5.1 mm completed in 17.27
  seconds including the 7--10 second process load.
- Editing a late Solid Fillet from radius 10 mm to 9.5 mm and then exercising
  Undo/Redo succeeded. The whole process took 36.25 seconds including load; its
  dependent suffix remained approximately 26 seconds.

The last timing is still too slow. Fillet, Chamfer and Shell already use their
own evaluator branches, and `Up To` is treated as a dependency rather than a
global barrier in the research planner. Production history batching is not
enabled because its representative probe lost an intersection source face at
the required input boundary. Stable edge/face identity, oldest-face ancestry
and exact feature boundaries take precedence over the measured shortcut.

## Compatibility and verification boundary

The authored native format and factory assets are unchanged. The new continuation
map is bounded, in-memory and disposable; no required sidecar is introduced.
Geometry precision, side identity, oldest-face ancestry, stable references,
persistence, Undo/Redo and protected placement remain unchanged. The Windows
and Linux dependency pins remain aligned at OCCT 8.0.1 and Qt 6.11.0.

Focused Windows Release verification passes model calculation, Opening variants,
operation activity, Save/Save As analysis, nested Part/Assembly Body Properties,
deferred exact face measurement, exact-radius Thin Extrusion and Sweep, native
history recovery/deletion, Fillet/Chamfer GUI paths, translation coverage and the
synthetic Skeleton activation/context-menu/Up To workflow. No user-visible text
was added, so all five localization catalogs remain unchanged.

The general native-style hover test still depends on a real foreground Windows
cursor and failed in this automated desktop with the cursor outside its test
window; the affected source was not changed. Immediate Escape termination is
also not included: safe cancellation requires cooperative OCCT progress tokens
and private-candidate checkpoints, not forced thread termination.

Native Linux compilation and execution are not established by these Windows
checks. Windows publication acceptance, signed asset digests and trusted updater
discovery will be added only after the committed candidate passes the release
pipeline.
