# Windows 2026100503

Status: implementation and focused native verification completed; Windows
packaging and publication acceptance are recorded after validation below.

## Behavior

Revolution Up To accepts exact original general surfaces and planes that do not
contain its axis. The established oriented-angle path remains for uniform planar
ends. Nonuniform ends use exact circular contacts and a clipped native overrun;
the display mesh never defines the calculated cap. Symmetric ends mirror their
target across the profile plane. Unreachable or ambiguous limits are rejected.
Sketch curve/point parents, cap-region identity and authored side choices persist.
Twist is unchanged.

Two joined limited sectors retain their exact Boolean trims. OCCT same-domain
unification incorrectly replaced one valid cylinder sector with its complement;
the regression checks exact validity, independent volume integration and twice
the single-side volume. This exception applies to the new exact-limit path,
without changing ordinary uniform rotations or the shared placement contract.

Drafted Extrusion Up To retains exact end-rim and endpoint ancestry. A surface
result with a curved free end drafts its overrun before clipping because OCCT
cannot reliably draft that already trimmed free rim. The solid path remains
clip-then-draft. Positive and negative draft angles are verified.

**Surfaces from solid** is a separate command with its own vector icon. It uses
the Shell lifecycle, zero thickness in the existing native field and no thickness
control. Exact remaining faces form connected zero-volume surface shells;
optional removal may produce openings or disconnected pieces. Input material
faces are selectable, independent surfaces retain their original ownership and
surface faces use the established yellow appearance. Editing cannot convert a
surface skin into a thick Shell. Family exposes no thickness parameter.

Fill and Trim allocate extra window height to their lower tables. Sewing and
Intersection keep compact two-row tables and top-anchored fields. New text is
translated into cs/en/de/fr/ru; project documentation is English. Creation and
editing share the existing internal Properties dialogs, real input rollback,
common picker, OK/Cancel and middle-button confirmation. Unchanged OK performs
no calculation or Undo transaction.

See [the implementation note](../SURFACE_UP_TO_AND_SOLID_SKIN.md),
[surface commands](../NETWORK_SURFACE.md) and [Shell CLI](../SHELL_COMMANDS.md).
The existing native fields and factory-template structure are unchanged; the
actual GUI checks create new editable Parts from the tracked start template.

## Source verification

All fifteen focused suites passed. Seven geometry/reference/command suites took
41.54 s; eight layout/translation/GUI/dependent suites took 138.94 s. Evidence:
`build/cpp-windows-release/modeling-0503-final-core.xml` and
`build/cpp-windows-release/modeling-0503-final-gui.xml`.

Focused tests cover forward/reverse solid/surface limits, exact curved caps,
axis endpoints, symmetric volume, source changes, cache invalidation, unchanged
confirmation, Undo/Redo, native save/reopen and cold regeneration. Draft tests
include both signs on exact general surfaces. Skin tests independently check box
and sphere area, zero volume, disconnected pieces, source edits, mixed Bodies
and downstream surface Fillet. Actual GUI tests exercise reference selection,
face removal, Cancel, persistence and reopening. Layout and translation tests
cover all five languages at 1366×768 and 1920×1080.

Synthetic native curved-rotation calculation measured about 90–100 ms on this
Windows Release host. This is not a promise for arbitrary target geometry.
Existing Fill opening/unchanged-confirmation operation counts remain verified.
Existing saved geometry is replaced only by explicit Regenerate.

The existing extrusion-axis endpoint contract failure (expected 20 mm, observed
20.635083 mm) and surface-profile hidden-sheet point failure were independently
reproduced on published-source 2026100502. They are not introduced by this change.
The prior broader regression limitations remain; a repository-wide green result
and Linux acceptance are not claimed.
