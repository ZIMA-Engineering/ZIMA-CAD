# Windows 2026110401 — Sketch editing and point-based Trim junctions

This Windows release repairs the reported Sketch dimension, constraint, Trim
and placement-presentation cases while preserving one shared C++ implementation
for Windows and Linux. Qt remains pinned at 6.11.0 and OCCT at 8.0.1. Native
Linux execution remains separate host work.

## Sketch editing

- Dimension changes in line-only profiles containing Parallel or Perpendicular
  relations can use the existing bounded simultaneous seed after an ordinary
  solve stalls. Successful ordinary solves and unsupported curve graphs retain
  their previous paths.
- Parallel and Perpendicular accept a base axis or straight read-only external
  reference as either the first or second GUI selection. The native Segment
  remains the driven participant and external geometry remains immutable.
- A finite line-to-line distance now starts its witness lines at the two Segment
  midpoints instead of leaving them visually detached in the Sketch plane.
- Mirrored circles persist Equal Radius with their source, so later R edits keep
  both the reflected geometry and its Trim boundaries associative.

## Point-based Trim topology

- Exact tangent line/circle queries classify only scale-aware discriminant
  round-off as a single root instead of manufacturing two microscopic roots.
- A persisted C+T Segment-to-Circle/Arc contact is the authoritative single Trim
  boundary. The reconstructed Arc reuses the exact native Segment endpoint,
  retains T and removes only the redundant C equation.
- Removing T after Trim leaves the shared point and Arc/Segment incidence intact.
  Real secant crossings and unrelated nearby points are not merged, and no global
  tolerance is enlarged.
- Analytical Segment/Circle contacts also split reflected Trim topology when a
  display chord would otherwise miss the exact tangent endpoint.

## Feature and placement presentation

- Changing an existing material Feature to Sketch no longer reuses a stale
  profile-frame validity flag from the previous feature type. Reverse conversion,
  Cancel, Undo/Redo and save/reopen use the same resolved placement path.
- A pending placed-container Origin replaces its previous preview after numeric
  edits while the active Body Origin remains visible. OK and Cancel remove only
  the pending frame.
- A newly committed internal Revolution, or a Feature newly changed to a
  Revolution side, enables its selected construction axis in 3D. A later edit
  does not override an intentional manual hide.
- Failed modeling definitions remain inspectable and saved. Later Features may
  calculate from the last valid body; repair and Undo/Redo preserve both the
  unresolved owner and the valid continuation.

## Verification boundary

The Windows regression matrix covers dimension kinds, both relation selection
orders, original and mirrored orientations, driving/reference and locked states,
successive numeric edits, repeated point drags, independent equations, atomic
rejection, dependent Trim, Undo/Redo, native save/reopen and actual GUI mouse and
dimension-editor interactions.

Focused point-based Trim checks cover both Segment endpoint orders, source and
reflected circles, base axes enabled, radius changes, dragging, T removal, GUI
preview and confirmation, Undo/Redo and Save/reopen. The complete Sketcher,
profile-command, Assembly-profile, tangent-contact, trimmed-Arc, Mirror,
placement-Origin and Feature-type contracts pass. The Czech, English, German,
French and Russian catalog contract passes; this release adds no user-visible
text or catalog key.

The reported `01.prtz` was inspected read-only and was not committed or packaged.
No native document format, protected shared container-placement solver, geometry
side identity, oldest-face ancestry or OCCT operation changed. Candidate and
signed publication require the repository packaging pipeline to pass exact
committed-source, dependency, archive path/collision/CRC/SHA-256, all factory
native-asset, GUI/CLI identity and fresh-extraction smoke gates.
