## Behavior

**Thicken Surface** (`Zesílit plochu`) selects one calculated free face in the
active editable Body and builds a solid by its normal thickness. First side,
second side and symmetric modes retain the oriented source-face side choice.
Symmetric thickness is the total; half is placed on each side. Curved faces use
normal offsets, not an extrusion along a fixed vector. Invalid or self-interfering
solids are rejected without committing pending edits.

Only the selected face is consumed. Other shell faces remain surfaces. The normal
Add Boolean path joins contacting or overlapping preceding material and retains
unrelated free surfaces. The original operand contains only the new solid.
Native caps, walls, rims, longitudinal edges and points retain their face/edge/
point parents. Source geometry edits invalidate dependent reference-mesh reuse.

OCCT's simple offset builder can return a reversed outer solid wrapper even
though its geometry, volume and B-Rep are valid. A forward wrapper carries the
same cumulative child orientations, enabling dependent Fillet without changing
geometry, tolerance or topology parents. The correction is local to this command.

The new icon and command use the surface group. Creation and editing share one
internal Properties window with the common required replacement field,
independent eye, numeric lock, OK/Cancel and middle-button confirmation. Opening
publishes the real input scene once. Draft edits do not calculate geometry;
unchanged OK creates no transaction. Thickness has a dimension identity and is
available to Family while unlocked. History prerequisites and Undo/Redo follow
the existing shared paths. Protected container placement is unchanged.

Documentation is English and new UI text is translated into cs/en/de/fr/ru.
See [Thicken Surface](../SURFACE_THICKEN.md). Factory Part, Assembly and Skeleton
templates were regenerated and reopened with the current serializer; their
empty-history bytes were unchanged. Actual GUI creation from the factory Part
confirms active editable Body context and enabled modeling commands.

## Source verification

All ten focused suites passed in **114.33 s** on this Windows Release host:
history deletion, derived copies, shared property layout, translations, Family,
Shell, factory new-document GUI, boundary/surface command GUI, native Thicken
Surface and native Boundary Surface. Evidence:
`build/cpp-windows-release/modeling-0504-final.xml`.

The new native suite took **5.87 s** and includes exact plane volumes, all three
modes, source orientation, periodic cylinders, a spatial B-spline patch,
unrelated surface retention, contact/overlap unions, partial solid-skin
conversion, stable native children, source edits, mass properties, dependent
Fillet in all modes, numeric locks, Family, no-op, persistence, cold regeneration
and atomic invalid-edit rejection. Independent curved checks use exact annular
sector and cylinder volumes rather than area times thickness.

The actual surface GUI scenario took **12.80 s**, including the established
Fill/Sewing/Surfaces-from-solid/Revolution checks and the new Thicken workflow.
It verifies common picking, the icon, independent inspection, required-source
replacement, one opening publication, zero draft publications, exact solid
volume, rollback, unchanged OK, Cancel, Undo/Redo and middle-button confirmation.
The Properties screenshot was visually inspected. Layout/translation checks
cover all five languages at 1366×768 and 1920×1080.

These timings describe the test fixtures, not arbitrary-model performance.
Repository-wide acceptance and Linux are not claimed. The inherited broader
regression limitations recorded for [2026100503](2026100503.md) remain separate.
