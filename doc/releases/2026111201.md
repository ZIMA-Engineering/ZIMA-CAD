# Windows 2026111201 — Planar surfaces, robust STEP import and line bends

Status: Windows source and focused verification accepted; signed publication
acceptance is recorded below only after immutable release assets are published.
Native Linux acceptance remains a separate host gate.

Planar Surface creates a zero-thickness surface from an owned Sketch in its
selected work plane, including a signed plane offset. Nested closed profiles
become holes and disjoint closed profiles become additional surface regions.
Native circles publish their usual construction axes. The command uses the
shared Sketch properties workflow, has no extrusion-direction control and keeps
its authored Sketch wire for ordinary selection and inspection.

Line Bend now treats the selected Sketch line as the developed centre of the
bend and derives its single physical bend direction from the Sketch plane.
The obsolete reverse-direction parameter and its native field have been
removed. The command accepts 0–180 degrees, shows its angular dimension in the
cyan preview and restores that preview after returning from Sketcher. Oblique
lines terminating at real sheet boundaries no longer create artificial
endpoint cuts, triangular remnants or unusable downstream edges. Invalid lines
ending inside continuous material are rejected without replacing the last
valid body. The repaired sheet state can be unfolded and its straight boundary
edges can be used by following Bends.

The Line Bend and Sheet Cut Sketch buttons now share the compact work-plane
row immediately after the View reference field. The change reuses the existing
button, reference field and interaction behavior.

Large STEP assemblies no longer fail as a whole when individual imported parts
are invalid. Valid components remain available and invalid components are
reported and skipped. This release also includes the current associative Sheet
from Body and coloured exchange workflows, Flat work-plane control alignment
and the adjacent import/export interaction corrections committed since the
previous Windows release.

ZIMA Fillet now trims a route sweep at a safe tangent or oblique terminal
plane, including a route that begins on a preceding Fillet radius. The complete
selected centre line is checked against each retained half-space before the
base sweep is clipped, so a returning route is preserved rather than erased.
This corrects the reported `RADIUS.prtz` case where Fillet 03 crossed the
adjacent planar face. Explicit persisted terminal faces remain supported by the
calculation contract; a new endpoint solution-selector UI is not part of this
build.

Focused Windows verification covers Planar Surface geometry, nested and
disjoint profiles, offset planes, native circle axes, invalid open profiles,
save/reopen, cold regeneration, Undo/Redo, unchanged OK, command ordering,
properties layout, selection wire and the absence of an extrusion-direction
cue. The adjacent Line Bend, Flat, Bend, surface-profile, STEP import and
five-language localization contracts are also run before packaging. Fillet
verification includes the preceding-radius tangent-plane regression, returning
routes and recalculation of an isolated copy of the reported document.
Candidate and signed archive acceptance add committed-source, dependency,
archive, factory-library, GUI/CLI identity, save/reopen and rendered-output
smoke checks.

The change adds localized Planar Surface labels and Line Bend validation in
Czech, English, German, French and Russian. It intentionally changes the native
Line Bend contract by removing the persisted reverse-direction field; legacy
Line Bend definitions are not supported. Start templates and affected factory
assets are regenerated and reopened with the current serializer before release.
The protected shared placement contract, calculation tolerances, Qt 6.11.0 and
OCCT 8.0.1 remain unchanged. A complete repository-wide regression run and
native Linux execution are not claimed.
