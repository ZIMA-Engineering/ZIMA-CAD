# Windows 2026112504 — exact surface references and modeling repairs

Status: local implementation and factory verification completed. The committed
Windows package, signature and public-download gates remain open in the
[verification record](../verification/20261125-exact-surface-reference-plan.md).

This change makes general-surface placement use persisted exact mathematical
supports instead of display triangles. Explicit geometry calculation captures
the surface and its trimming boundaries. Point, normal and signed-offset solving
uses the shared C++ evaluator; ordinary reference entry does not invoke OCCT.
Missing supports retain the last valid frame and remain repairable.

The modeling changes since 2026112503 include:

- Preserve history-boundary references when a later Extrusion is added, including
  the reported POKUS5 Wrap/Surface sequence and dependent sheet attachments.
- Use XY consistently for Helical Curve/Sweep placement, including alignment to
  the first selected normal support, and retain usable centerline endpoint IDs.
- Add the Arc type to the spatial curve workflow and the sketch-owned planar
  Surface feature, with Surface available below Wrap relief in Modeling.
- Continue Project/Wrap over connected pieces of the same support; retain
  redundant selected rows while using one equivalent support in calculation.
  Explicitly selected different supports define the continuation chain.
- Preserve selected target faces when changing Project/Wrap feature types,
  remove meaningless ordering controls, and show signed relief depth in the View.
- Show the actual split between two-sided curved extrusion faces in the model
  View. Drawing defaults show visible and hidden edges and hide tangent edges.

The approved current native contracts are Part INI 57 / JSON 80, Assembly INI 39 /
JSON 51, and Drawing INI 22 / JSON 14. Extensions are unchanged. Required exact
data lives in the native documents; there is no required sidecar or legacy reader.
All 1,202 affected tracked factory/test documents have been prepared, verified
with the final native implementation and promoted locally. This includes a full
recheck after repairing analytic-support packet deduplication. Packaged verification is
still required. Protected TOYOTA originals have not been overwritten.

Local Windows verification includes exact surface values/derivatives, bounded
contacts, signed sides, native persistence, repeated regeneration, affected
Undo/Redo paths, actual placement/editing GUI, mm/in templates in all five
languages, and the POKUS5 downstream Extrusion regression. These are finite
matrices; arbitrary numerical global-root completeness is not claimed. Linux
execution remains unverified.

The protected older skeleton and sheet Part have pre-existing differences from
their saved geometry under the current modeling contracts. The committed prior
kernel reproduces those differences. The isolated current skeleton repeats with
identical geometry/references and its dependent Drawing passes. A second Drawing
has a missing source Part and cannot be claimed as regenerated. See the full
verification record for the import analysis and remaining acceptance gates.

An unchanged native shape now shares one physical integration across rigidly
placed analysis inputs. Independent integration tests verify transformed centers
and inertia tensors. The G92K1-100 user model performs one integration instead of
two; saved measurement inspection does not repeat it. Large-import integration,
serialization and Assembly source loading remain expensive. This release does
not claim that every large-model operation is fast.

CAM completion and Sketch contour dragging are the agreed next work after this
repaired release. They are not newly completed features of this checkpoint.
