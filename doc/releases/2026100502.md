## Behavior and cause

General Surface and Fill now verify the final B-spline's actual 3D/2D boundary
representations at document precision. OCCT's filling error describes its
intermediate plate, and the usual sampled shape check can miss an approximation
peak. In the reported `02.prtz`, the original circle boundary deviated by about
0.008674 mm despite a document tolerance of 0.001 mm and a reported plate error
of only 0.00008245 mm. Larger fillets exposed this existing mismatch.

The established degree-8/32-segment approximation remains the first attempt.
Only a deficient result triggers degree-12 fits capped at 64 and 128 segments,
with a fresh builder per attempt. Final boundary errors are checked independently;
an unsatisfied precision is rejected. Edge representation tolerances cover only
measured errors within document precision, without moving the authored curves.
Native ancestry, side choices and shared placement are unchanged.

Surface Fillet and Chamfer faces are classified individually as surface results
and use the existing yellow style (`#F2D34F`). Surface visibility includes them.
In a mixed shell/solid Part, unrelated solids and solid fillets retain their
ordinary classification and mass properties. The classification is stored with
existing native references; no native format or template change is introduced.

Existing calculated files require explicit **Regenerate** to replace their
saved approximation or classification. Opening, hovering, reference inspection
and unchanged Properties OK do not calculate geometry.

## Inputs, means, outputs and independent verification

Input: a disposable copy of the user's native model, two trimmed freeform
surfaces sewn along a 160.591340961 mm seam, with 0.001 mm linear precision.
Means: the native CLI and independent OCCT 8.0.0 diagnostics, exact shape
validation and continuous maximum curve/surface deviation checks. Output: a
precise input shell supporting feasible fillets without relaxing precision.

The regenerated copy retains 11 faces and 33 edges; the same original native
seam reference accepts R 1, 2, 5 and 10 mm. Exact validation passes and the
maximum input edge tolerance is about 0.000482 mm. Original projects remain
unchanged. A standalone six-curve regression reproduces the difficult arc
boundary and verifies precision, exact validity and native edge identities.
An unattainable 0.00001 mm request is rejected after bounded work.

The geometry suites also cover surface Fillet/Chamfer classification, surface
hiding, unrelated solids and solid fillets in a mixed compound. The GUI scenario
checks actual shell-edge picking, live and saved surface classification, edit,
Cancel, unchanged confirmation and Undo/Redo.

No user-visible text was added or changed. Existing localized errors are reused;
catalog/source coverage and the five-language UI translation contract are
required. Documentation is English.

## Measured cost

On the same Windows Release machine, three serial fresh CLI processes each
opened the original `02.prtz` and explicitly regenerated it. The median total
process time, including startup, file loading and regeneration, increased from
6.211 s on committed build 2026100501 to 8.939 s with the corrected surface
calculation (about 2.73 s / 44%). This is a correctness cost on this difficult
model, not a speedup claim or an isolated kernel timing. The final geometry is
more complex; downstream calculation cost is included in this observation.

An isolated six-curve fit took about 0.04 s for the original approximation and
0.19 s for its successful finer fit; final boundary checking took about 0.0015 s.
Several lower degree/segment alternatives failed document precision. Refinement
is limited to two retries and is absent for an already precise first result.
There is no additional interaction calculation or unbounded fitting loop.

Evidence: ignored `build/fillet-02-investigation/` diagnostics, native command
outputs, exact boundary checks and `performance.json`. Wall-clock observations
are specific to this model and host, not portable test thresholds.
