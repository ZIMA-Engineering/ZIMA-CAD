# ZIMA-CAD 2026092701 — Windows

This build adds explicit placement solution branches, parameter ordering and
transition attachment and interaction updates.

- Circle/ellipse and cylinder/plane placement remembers the selected branch,
  including passage through tangency. An unreachable branch becomes invalid
  without jumping to the other solution. The shared Solution branch field uses
  View picking and an independent inspection eye.
- Rectangular transition previews draw omitted profile sides and the omitted
  corner generator with dashed lines. Calculated material is unchanged.
- A Part can contain only one sheet transition, across all Bodies and both
  transition types. Editing that transition and attaching further sheet
  features remain available.
- Repeated solving of an already satisfied trimmed-edge attachment preserves
  the existing point. Changed source geometry is checked again with the same
  residual threshold; calculation precision is not reduced.
- Reference removal, internal-window close and tab close controls use a red
  background and white cross. Toolbar commands provide hover/pressed feedback
  from the system palette. Each control retains its existing action.
- Parameters use a separate ordering checkbox and bottom Up/Down buttons, as in
  3D Curve. Selection follows the moved parameter, including after changing the
  displayed language. Reordering preserves values and labels and commits only
  on OK through the existing native metadata transaction.
- Revealing the Solution branch field grows the internal properties window to
  its new layout minimum, within its parent bounds, so reference rows remain
  visible. Additional height still belongs below the anchored fields.
- Adjacent Bend/Sweep children publish their shared authored station point once.
  This removes a duplicate reference candidate that prevented downstream Bend
  attachment from settling. Point identities and body geometry remain unchanged;
  inconsistent positions beyond the kernel confusion tolerance are rejected.
- Confirming an unchanged calculated Bend reuses its geometry. If its calculated
  body is missing, OK calculates it without creating an unnecessary history edit.

Part JSON/INI versions are 66/42; Assembly JSON/INI versions are 46/34.
Branch definitions are stored in the native documents. Start Part, Skeleton
and Assembly templates use the current serializer. Older document versions
are unsupported; no migration or sidecar storage is introduced.

Changed messages are localized in Czech, English, German, French and Russian.
The development entry point remains repository-root `zima-cad.bat`.
Linux and Solid Straighten/Restore remain outside this release.

## Verification status

The six focused source tests and 20 wider regressions passed. The initially
failing Bend continuation was traced to duplicate shared station point
references, then fixed and verified by the full Bend command suite. That suite
also covers unchanged confirmation and reconstruction of missing calculated
geometry. The strengthened surface-placement GUI check passes after the window
layout fix, including inspection, resizing, persistence, Undo/Redo and Cancel.

Parameter table interaction, metadata persistence/Undo/Redo and five-language
translation checks passed. Related whole-Origin, Sweep, Sweep point reference,
compact-window, transition attachment, transition command and transition GUI
checks passed. Packaging unit tests passed (two platform-specific skips);
publisher tests passed all 16 cases. Start templates were regenerated and
new-document/template GUI checks passed again on the final source build.
The Windows 11 interaction colour and symbolic through-all checks passed.

The broader 300-case dialog layout audit still reports 20 failures: ten Sweep2D
profile-cell overflow cases and ten Linear Pattern table anchoring cases across
five languages and two window sizes. Rebuilding and running the same audit with
the preceding PropertiesSubWindow implementation reproduced exactly the same
20 failures. These existing layout limitations are outside this change; the
audit is not reported as passing.

Builds and tests were run serially following reported Windows crashes. Their
cause has not been identified or claimed fixed by these source changes.
