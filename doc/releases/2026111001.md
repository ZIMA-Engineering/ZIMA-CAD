# Windows 2026111001 — Profile extents, copy Origins and resilient Fillet routes

Status: Signed Windows release candidate pending publication acceptance.

This build supersedes the unpublished 2026110901 and 2026110902 source tags. It
contains their 3D Sweep rollback, projected-view placement, Drawing display,
Sketch Trim, Pattern/Mirror Origin and Bend-aligned Sheet Profile corrections,
then completes the remaining Profile, reference and edge-treatment work.

Sheet Profile now uses the shared Feature extent model. A free Profile supports
Forward, Reverse and Symmetric direction, independent Side 1 and Side 2 lengths,
and one Up To point, plane or planar-face target per side. Symmetric dimensions
show the distance on each side rather than the combined width. An edge-attached
Profile derives its complete interval, thickness and initial Bend frame from the
selected sheet edge and exposes no conflicting manual width controls. Its owned
Sketch and generated Bend/Flat children remain one Profile for ordinary
selection and dimension inspection, while the attachment Bend remains editable
through its established exception. Explode, Undo/Redo and save/reopen preserve
the authored route and stable child identities.

The authored Sheet Profile contract advances native Part format 49 to 50 and
the internal serialized packet from 73 to 74. All 1,058 repository-owned
Part-based assets were regenerated with the current implementation, including
1,030 factory library Parts, four start templates, frame/title-block assets,
ten symbols and twelve test fixtures. The metadata-only native reader now uses
the same format-50 gate as the full Part loader. No legacy-format fallback was
added.

Entering an owned Sketch automatically displays only the active Body's main
Origin. Its point and three axes are selectable. Origins manually shown for
earlier history containers and Pattern/Mirror copies remain selectable and their
external Sketch references survive regeneration, source movement, suppression,
repair, Undo/Redo and native reopen while retaining the last valid frame after
reference loss. Axis and Plane construction elements retain their ordinary
visibility rules; no second automatic publication system was introduced.

Pattern and Mirror preserve independent copy topology, including stable solid,
face, edge, vertex and copied-Origin identities through nesting, regeneration
and persistence. ZIMA Fillet and Chamfer now treat Feature Start/End halves as
one logical rail only when their exact persisted endpoint graph forms one open
chain. A disappearing or newly appearing half is resolved without rewriting the
authored selection. Unrelated halves are never merged. Exact coplanar 180-degree
return routes use a stable binormal and pass reversed-order and multiple-radius
calculation checks. Inactive Revolution axis endpoints remain available when a
Feature changes operation.

The final focused Windows Release matrix passed 22/22 native and GUI contracts,
including the complete shared UI contract, Profile geometry/UI, copied origins,
derived-copy commands and topology, Sketch external references and repeated
dragging, Fillet route queries/calculation, native documents, metadata, work
planes, both direct/command edge-treatment paths and all five localization
catalogs. The separate workspace-startup suite
still reports its pre-existing second-active-Body Tree/View menu assertion after
all preceding startup, import, Save Copy and placement checks pass. Native Linux
compilation and execution remain a separate host gate.

No protected shared container-placement implementation, geometry-side meaning,
calculation precision or dependency pin changed. Windows and Linux retain one
shared C++ implementation with Qt 6.11.0 packaging and OCCT 8.0.1.
