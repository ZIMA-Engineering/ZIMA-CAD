# Windows 2026110801 — Fillet selection and profile-frame stability

Status: Windows source candidate pending.

Fillet and Chamfer selection now reconstructs the complete analytical authored
cage from every persisted route on the already calculated operation input. Each
route shows two longitudinal boundary rails and its two terminal Fillet arcs or
Chamfer lines, not only the source/control edge. Later Boolean fragments no
longer decide which creation/Properties strokes are shown. Ordinary selection
remains wire-only, extracts no calculated result edges, performs no OCCT
calculation and does not modify the document. Opening treatment Properties
retains the real rollback Body, and Cancel restores the complete history without
a transaction.

Automatic connected-edge selection stops when a tangent edge continues onto a
different material-side pair, even if both wedges have the same opening angle.
True line/arc and split-edge continuations remain connected. This prevents the
reported extra segments beyond a visible break while preserving exact authored
route identity. An edge generated by an earlier Fillet or Chamfer is traversed
when its exact tangent continues forward with the same material-side pair. Its
semantic identity alone no longer truncates a valid current-Body route. A
tangent curve returning along the incoming side, a changed material pair and an
ambiguous branch remain terminal.

Calculation preserves the user's explicit route membership. A standalone
additive edge stops at the beginning of an unselected earlier Fillet arc and is
never extended to a remote face. Explicitly selecting that tangent current arc
as a separate item joins both items into one continuous single-tool route; the
shared vertex is not trimmed as two ends. A standalone subtractive edge may
continue through an earlier arc to its next planar cap only when a material
probe confirms that the removal wedge continues in that direction. Otherwise
it stops on the arc. The direct regressions cover additive stop behavior,
separately selected tangent line/arc joining, subtractive continuation
and automatically detected planar termination at small and large radii.

Every route member already shown in Properties is now authoritative for both
the azure preview and calculation. A mixed source-edge, earlier-treatment-arc
and Boolean-split route is no longer post-filtered to two members, so the
intermediate arc appears in the View and produces its corresponding treatment.
Automatic stop decisions still occur while constructing the route, before it is
persisted.

Automatic curved termination distinguishes a preceding Fillet from a Body
terminal split into several trimmed faces. A preceding Fillet which alone meets
both route supports remains an exact stop. Pieces proven to belong to the same
analytical cylinder, cone, sphere or torus are combined as one terminal; the
treatment tool is locally extended and clipped by the complete analytical
surface. This fixes `12.prtz` Fillet 01, whose end must follow the circular
cylinder instead of a finite face patch, without changing the correct additive
stop behavior of `11.prtz` Fillets 13, 15 and 19.

A compound local end where different curved faces continue the two route
supports is now kept distinct from a split copy of one analytical surface.
`11.prtz` Fillet 09 therefore terminates at its local cylinder/Fillet edge and
does not continue to a remote Body cap. When a new profile is larger than a
preceding cylindrical, spherical or toroidal radius, ZIMA may overgrow only its
internal construction tool and clips the final result by the exact curved
surface. No approximate overrun is retained in the Body.

Body-wire publication now hides a smooth two-face cylindrical junction only
when both faces are pieces of the same radius and coaxial cylinder. A real
tangent boundary between geometrically different cylinders stays visible. This
restores the missing Body edges reproduced in `12.prtz` without exposing true
one-face parameter seams or same-cylinder split lines.

ZIMA `A x B` and `A + angle` Chamfer now accepts one connected, unbranched route
containing multiple straight segments, including a route which turns across
support faces. The first segment defines the A-side and that support role is
transported through every continuation. Reversed member order is geometrically
equivalent. Disconnected selections, branches and ambiguous support-role
continuations are rejected atomically.

Deleting an earlier treatment now keeps any later dependent treatment visibly
broken for manual repair while preserving selectable stable identities on the
surviving current Body. A rare shortened-history packet with display geometry
but no valid edge owners is republished once from its calculated source; normal
deletion retains the incremental warm path. Cold native continuation also
propagates its live, non-persistent calculation proof to byte-unchanged reused
prefix packets. Neither correction changes native storage.

With the user's explicit approval, a newly selected or replaced first planar
support in automatic profile mode now authors TOP/local XY instead of retaining
the generic FRONT/local-XZ candidate from placement row zero. Existing persisted
FRONT frames, manual work planes and complete-Origin entry are not silently
migrated.

The exact `10.prtz`/`11.prtz`/`12.prtz` reproductions, focused native matrices and all five
localization catalogs are part of the Windows candidate gate. No user-visible
text changed in these fixes. The Windows
committed-source candidate, signing and publication remain to be completed. The
native format, factory assets, start templates, geometry precision and Qt/OCCT
8.0.1 pins are unchanged. Native Linux compilation and execution remain a
separate host gate.
