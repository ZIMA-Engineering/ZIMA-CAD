# ZIMA-CAD 2026101303 — File Manager and large-model follow-up

## Changes

File Manager opens supported STEP, IGES and DXF previews even when the Preview
cell has no thumbnail. Native parameter columns read the bounded parameter
sections without constructing the complete calculated model. Saved parameters,
their five-language labels and localized values are also mirrored in directory
metadata for other consumers; open unsaved documents remain authoritative in
memory. Native files retain the established document format.

Directory Properties exposes independent parameter and thumbnail source lists,
with relative paths, recursive lookup, cycle validation and local overrides.
Included sources remain read-only. Native filename icons use the shared file
dialog mapping, including numbered backups and theme changes. Template cleanup
respects existing inherited removal protection and explains disabled actions.
Thumbnails retain aspect ratio while removing verified exterior backgrounds.

Imported Extrusion resolves pending Body-local profiles through their owning
Body carrier, including Parts with a following empty Body. The protected shared
placement solver is unchanged. Native INI loading avoids repeated large string
copies. Confirmed selection wire uses the same screen rectangles through convex
polygon rendering with one painter state. Imported rational STEP properties
reuse existing ordered parallel integration at the unchanged tolerance.

All product changes use shared Windows/Linux C++. OCCT remains 8.0.0; native
formats, factory definitions and persisted geometry/reference contracts are
unchanged. New UI labels and errors are translated into cs/en/de/fr/ru.

exact selected endpoint images. Full native load/save/reopen retained complete

imports retained every persisted property snapshot exactly.

Thirteen of fourteen final scoped contracts pass; the general UI suite stops
at its command-hover/native-Qt-style assertion on this host. Independent
interaction-color and curve-presentation matrices pass. Focused foreign preview
passes; the full preview suite retains a datum-marker/camera failure. These are
explicit verification gaps, not a claim of a complete repository-wide pass.

The representative G92K1 STEP import still takes 692 seconds, dominated by
607 seconds of precise GK volume integration. No substantial total import
speedup or completed serial G92K1 equivalence comparison is claimed. Linux
execution remains assigned to the Linux host. Engineering-table work is deferred.
