# Windows 2026110303 — routed edge treatments and calculated Sketch references

This Windows release strengthens the ZIMA Fillet/Chamfer construction path,
history-boundary durability and Sketch references to calculated treatment
geometry. The product remains one shared C++ implementation for Windows and
Linux. Qt 6.11.0 and OCCT 8.0.1 stay aligned across the native build recipes.
This record establishes Windows execution only; native Linux build and GUI
acceptance remain separate host work.

## ZIMA Fillet and Chamfer

- Fillet and Chamfer Properties offer Automatic, ZIMA and OCCT as three mutually
  exclusive calculation choices. Route members are listed directly in forward
  geometric order without an expandable parent row.
- Hover highlights only the exact candidate edge. Confirmation and the cyan
  preview show every accepted route segment. A route crosses only one unique
  forward-tangent continuation; a tangent reversal, branch or ambiguity ends it.
- ZIMA Fillet uses the exact circular-arc-and-two-lines section. ZIMA Chamfer
  uses its exact three-line section. Neither adds an arbitrary outside extension;
  comparisons use the document's configured modeling tolerance.
- A Fillet route may mix supported straight and circular segments. Section
  construction starts inside each segment so both terminal conditions can be
  completed independently. Chamfer retains its supported straight-route scope.
- Empty ends remain perpendicular to the route. A valid explicitly selected or
  automatically inferred planar end face clips the first or last route endpoint,
  including an angled face. A face that does not contain the endpoint is rejected
  before calculation. Explicit OCCT mode does not accept ZIMA end faces.
- A selected authored/original edge remains an explicit single-edge operation.
  Current-result routes follow all surviving exact descendants and remain
  resolved while any persisted source fragment survives an upstream edit.
- Same-domain cleanup removes only newly redundant coplanar seams while retaining
  authored boundaries and their ancestry. Unsupported ZIMA cases fail explicitly;
  Automatic may retain the existing OCCT path.

Variable-radius Fillets, arbitrary spline routes, general free-form adjacent
faces, unrelated hole-intersection restoration and advanced multi-face terminal
transitions remain future extensions.

## History and failed-feature durability

- Each history boundary publishes its own exact calculated reference packet.
  A failed producer cannot substitute an older cached boundary and thereby
  rotate, mirror or reorder a later placed container.
- A structurally valid Fillet or Chamfer may be committed and saved while its
  current geometry is unresolved. It stays visibly failed in history so a later
  feature can also be authored and the broken source can be repaired in context.
- Removing or repairing a failed treatment resumes calculation from persisted
  history without changing the placement or Sketch coordinate system of an
  earlier container.

## Sketch references to calculated treatments

- Ordinary Reference and Reference Profile accept exact result edges generated
  by Fillet and Chamfer. Finite open edges retain independently selectable start
  and end references; Reference Profile creates linked native line, arc, circle
  or spline geometry with the source's analytic type when available.
- A selected circular planar face, or a cylindrical face whose axis is normal
  to the active Sketch, creates a read-only circular reference. Reference Profile
  creates the corresponding linked native circle. Invalid or oblique face input
  is rejected without modifying the Sketch.
- Generated-edge references follow the persisted Fillet/Chamfer source identity,
  never an anonymous OCCT enumeration index. Editing the treatment, Undo/Redo,
  native save/reopen and a cold history calculation retain the reference and its
  analytic geometry.
- Reference Outline is one white line with compact brown endpoint crosses.
  Intersection Outline keeps the Intersection symbol and uses a white line with
  white endpoints. The icons remain distinct at normal toolbar size.

## Perpendicular Sketch junctions

- Dragging the shared native point of two perpendicular lines projects the
  requested position onto the exact perpendicular-junction locus.
- Applicable length edits seed the ordinary solver from the analytic locus
  intersection. Repeated edits and drags retain the original shared point and
  perpendicular equation; impossible edits leave the document unchanged.

## Architecture direction

The roadmap now records the agreed progressive ownership boundary: ZIMA will
increasingly own authored profile, path, transported-section, Sweep/Loft surface
and semantic-ancestry construction. OCCT remains the supported B-Rep/topology
backend for trimming, sewing, intersections and Boolean operations. This is an
incremental shared-platform direction, not an immediate OCCT replacement.
