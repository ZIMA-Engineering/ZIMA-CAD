# Windows 2026110301 — native edge treatments and workflow corrections

This Windows release introduces the first production ZIMA construction path
for planar Fillets and Chamfers, while retaining OCCT as an explicit alternative.
The product implementation remains one shared C++ source for Windows and Linux,
with Qt 6.11.0 and OCCT 8.0.1 aligned across the native build recipes. This
record establishes Windows execution only; native Linux build and GUI acceptance
remain separate host work.

## Fillet and Chamfer construction

- Fillet and Chamfer Properties offer mutually exclusive Automatic, ZIMA and
  OCCT calculation methods. Automatic uses the supported ZIMA construction and
  retains the existing OCCT route outside that supported boundary.
- The ZIMA path constructs supported straight planar edge treatments as explicit
  profile extrusions and Boolean operations. Fillets and Chamfers have separate
  native builders and do not duplicate their modeling implementation per OS.
- Every selected route has independent first and last end-face slots. A valid
  planar end face clips the treatment at the route endpoint, including an
  angled face; an empty slot keeps the perpendicular end. Automatic end-face
  inference may populate a valid endpoint face. Delete clears an inferred or
  explicit value without deleting the route.
- End faces are rejected when they do not contain the corresponding open-route
  endpoint. They are unavailable in explicit OCCT mode. Invalid input is rejected
  before calculation instead of reaching an unsafe kernel call.
- Stable selected-edge ancestry follows surviving calculated fragments. If one
  fragment disappears after an upstream edit, the treatment remains resolved
  while at least one fragment of the selected source route survives. The cyan
  preview publishes every matching current fragment instead of only the first.
- The existing route/Object GUI is retained. Properties expose the additional
  end controls without changing route ownership or the protected shared
  container-placement contract.

The current ZIMA builders intentionally cover straight routes with supported
planar adjacent faces and planar clipping faces. Curved routes, arbitrary blend
transitions, treatments intersecting unrelated holes and advanced termination
shapes remain future extensions. Automatic preserves a usable fallback; explicit
ZIMA reports an unsupported case instead of silently changing modeling intent.

## Modeling and interaction

- New history commands start collapsed in the Tree. Explicit user expansion is
  still preserved during ordinary refresh.
- Pattern copies of Thread operations retain transformed primary axes with stable
  copied identities through native save/reopen and Undo/Redo.
- New Hole creation keeps dependent controls disabled until the first valid
  placement reference is entered. Editing an existing Hole starts with its
  established parameters available.
- Feature Properties removes the redundant Point and Text check boxes. The
  feature point remains available through normal confirmed feature inspection.
- Body Properties places Visible beside Active Body. Body measurement keeps the
  complete Origin visible while presenting the calculated centre of mass.
- With the Part root active and no Body active, Modeling and Sheet Metal command
  selectors are hidden. The root context exposes Create Body, Body Mirror,
  Body Pattern, Body Scale and Boolean operations.
- Assembly Component Properties publishes pending X/Y/Z and RX/RY/RZ dimensions
  in the View. Dimension double-click edits the pending component placement;
  OK commits it and Cancel leaves the occurrence unchanged.
- Removing the final orientation reference folds the resolved frame into the
  persisted absolute placement. A placed imported component therefore does not
  rotate after its last reference is removed.

## Sketch references and File Manager

- Every finite open external Sketch edge now owns selectable start/end
  references in addition to the edge itself. This includes straight edges,
  arcs, open splines and individually selected face-outline generators; closed
  and infinite curves do not invent endpoints. The brown reference cross is
  larger, and normal, hover, confirmed and box-selected presentation all remain
  a cross rather than changing into an indistinguishable point glyph. Parent
  deletion removes the derived endpoints, and their identities survive refresh,
  native save/reopen and Undo/Redo.
- File Manager reuses the first View-toolbar action as Refresh. F5 regenerates a
  CAD document in a CAD tab and refreshes the file list, native metadata,
  thumbnails and HTML Overview in a File Manager tab.
- Refresh invalidates the native metadata cache before reloading. Localized
  legacy Pro/ENGINEER column identifiers such as the Czech mass label map to the
  canonical native mass value while edits continue to use the canonical key.

## Native format 48

Part INI format 48 / internal JSON format 72 makes the edge-treatment calculation
method and the two end-face slots per route mandatory. The production reader is
strict: legacy Part formats are intentionally unsupported, in accordance with the
native-format policy.

All 1,046 repository-owned Part-based factory assets, including both Part and
Skeleton start templates, FORM definitions, title blocks and symbols, were
calculated with the changed implementation, saved as format 48 and reopened.
The conversion verified authored histories, Sketch identities, calculated
geometry/reference contracts and native readback. It covered 1,236 persisted
Fillet/Chamfer definitions and preserved their existing OCCT method and
perpendicular ends. User-authored libraries were not overwritten.

The twelve remaining format-47 native test fixtures were independently upgraded
from authored history, regenerated and reopened. Exact native readback, unchanged
authored history and calculated-contract preservation passed for every fixture.
The explicit offline migration tool retains OCCT for existing edge treatments;
the strict production reader has no legacy compatibility branch.

Obsolete numbered native copies were removed only where the corresponding main
file existed. This removed 2,046 redundant files and recovered 895.1 MiB. The 28
numbered files without a main counterpart and the complete pre-conversion project
backup were deliberately preserved.

## Verification boundary

Focused native and GUI checks cover the three calculation methods, Fillet and
Chamfer construction, perpendicular and angled termination, invalid endpoint
faces, fragment survival, cyan preview publication, collapsed Tree rows, staged
Hole entry, copied Thread axes, placement-reference removal, Assembly placement
dimensions, mass-Origin visibility, root-level Part commands, external edge
endpoints, File Manager refresh, all five localization catalogs, native
save/reopen and Undo/Redo.

The final Windows source candidate built all 256 configured Release targets.
The focused Fillet, Chamfer and Hole GUI matrix passed 6/6. Factory selection
preview checks, the start-Part GUI contract, File Manager workflow, localization
coverage, native document, calculated-model and document-session contracts also
passed. The start-Part check created the document through the real configured
template, verified its active editable Body and enabled normal modeling commands,
then saved and reopened the result.

The isolated `POKUS.prtz` verification changed Fillet06 from OCCT R12 to ZIMA
R17 while the preceding Fillet05 remained R15. Calculation, save/reopen and the
following Hole and Pattern succeeded, confirming that the preceding radius does
not impose an artificial upper bound. A synthetic Boolean test separately
verified two surviving source fragments, one surviving fragment and unresolved
state only after all selected ancestry disappears.

The complete 517-test development corpus is not represented as fully green. An
earlier serial diagnostic sweep passed 392 tests; remaining observations include
environment-dependent legacy tests and six older command tests that inspect a
deferred raw volume without requesting physical analysis. The focused contracts
for the changed behavior pass, but this release record does not hide that broader
verification boundary.
