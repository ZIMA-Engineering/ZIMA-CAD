# Windows 2026100302

Status: source implementation verified; packaging and publication pending.

## Changes

- Keep canonical millimetres/degrees across model authoring, View dimension input,
  symbols, Family and mixed-unit nested Assemblies. Explicit dimension input such
  as `0,254inch` converts without changing document units or physical geometry.
- Preserve exact unchanged values and manufacturing annotation precision. Convert
  complete finite decimal specifications exactly; otherwise retain the original
  specification with a marked approximate secondary nominal.
- Convert typed Relations and cached numeric outputs atomically on document-unit
  changes, preserving inactive branches, trigonometric conventions and Undo/Redo.
- Preserve physical mass, area and volume for repeated/nested mixed-unit sources,
  including current unsaved source changes and saved measurements.
- Refresh View units/precision and centroid coordinate tooltips immediately on
  metadata edits. Correct unit labels in Sweep selections and correspondence data.
- Verify native-template precedence, STEP/IGES import, STEP export, Drawing scale,
  actual DXF annotation strings and independently rendered PDF output.
- Include the previously verified mixed Feature-side rotation and chained Sketch
  fillet fixes since the previous Windows release.
- Maintain cs/en/de/fr/ru localization and English user/developer documentation.

## Verification and limits

Incremental native and GUI evidence is recorded in
[the unit audit](../DOCUMENT_UNITS_AUDIT.md). Final symbol/input/native/export/
localization suites passed 7/7 in 48.32 seconds. Configured in/rad New Document
creation passed in all five languages in 34.04 seconds. Eight exported PDFs have
identical independently rasterized pages with readable manufacturing tolerances.
These are regression timings, not interactive performance claims.

Thread standards/catalogs, geometric precision, persisted reference sides and
kernel tolerances retain their existing contracts. IGES is import-only. Physical
printer-driver and Linux GUI acceptance are not claimed. Optional Family CSV,
first-run setup, Boundary Surface redesign, File Manager and extended Drawing
captions remain separate follow-ups.

Only committed source and factory configuration may enter the package. Personal
settings, backup documents, screenshots and test outputs remain excluded. The
root development launcher stays `zima-cad.bat`.
