# ZIMA-CAD 2026101401 — STEP interaction and native-save performance

## Changes

New Feature profiles retain the complete cyan analytical wire after returning
from Sketcher, including profiles drawn on STEP faces in placed Bodies. Feature
extent manipulators and transient dimensions consume the owning Body frame.
Properties can reopen saved incomplete Features for inspection and repair.
The protected shared container-placement panel, solver and dimension-entry
contract are unchanged.

Reference-only Feature/Point/Axis/Plane/Curve history additions retain unchanged
calculated material without remeshing or reintegrating it. Cold material edits
still rebuild real source topology and ancestry. Surface projection in result
edge preparation reuses operation-local OCCT surface initialization with the
same point searches, bounds, precision, normals and side choices.

Native Part saving releases transient JSON/text before its complete validation
reload, avoids retained duplicate large-string keys and reuses exclusively owned
JSON allocations during lossless cache packing. The native format, required
document data, atomic replacement and full validation remain unchanged.
Confirmed azure wires draw the same ordered screen segments in one painter
batch. Imported high-span STEP integration splits independent trim work while
retaining ordered exact accumulation and the existing tolerance.

All changes use shared Windows/Linux C++. OCCT remains 8.0.0 and Qt 6.11.0.
No user-visible product text was added; all five localization catalogs were
reviewed and their translation contract passes. No native schema or factory
asset format changes are introduced.

## Measurements and finite verification

On the user's immutable `02.prtz` investigation copy, the last 50 mm subtraction
decreased from 96.1 to 53.3 seconds with an identical complete final Body packet.
Native save decreased from 114.8 to 63.4–74.4 seconds with unchanged complete
definition/calculated-packet hashes and the same 646,622,704-byte file. The
intermediate implementation measured 85–95 seconds. These are host observations,
not universal timing guarantees; cold STEP rebuild, serialization and complete
save validation remain substantial costs.

The representative G92K1 backend import decreased from 692.0 to 520.6 seconds,
with exact saved physical properties and complete native-packet equivalence.
Selected rotation decreased from approximately 140 to 73–79 ms. Wire/edge
images are exact in the recorded comparisons; shaded images differ by at most
one channel level at one or two pixels.

Evidence, exact hashes, operation counts, small/large fixtures and the exercised
GUI/native matrices are recorded in:

- [STEP scheduling](../performance/20261014-step-gk-face-investigation.md);
- [placement preview and rotation](../performance/20261014-step-placement-preview-investigation.md);
- [reference-only history and incomplete Features](../performance/20261014-step-datums-and-dimensions.md);
- [last Extrusion and native saving](../performance/20261014-step-last-extrusion-and-save.md).

The native/GUI contracts cover STEP properties, reference-only history,
Part/Assembly profiles, construction, Body properties, cached persistence,
wire return, repeated length edits, independent plane equations, incomplete
Feature reopening, Undo/Redo and Cancel. Existing Sketch dimension/reference,
profile-frame and dimension-entry suites also pass. This is finite coverage,
not an exhaustive imported-support Sketcher edit/drag/contact-side matrix.
Two broader GUI harness assertions remain documented baseline gaps; a
near-parallel shared-panel diagnostic is recorded separately and no broader
placement rewrite is included. Linux execution and timing require the Linux host.
