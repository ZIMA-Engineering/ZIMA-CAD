# Windows 2026102802 — intersection-aware edge treatments

This Windows release follows `2026102801` with a focused correction to Fillet
and Chamfer selection on Boolean-generated geometry. The fix preserves both
the actual cross-feature intersection and the surviving original edge as
independent selectable modeling references.

## User-visible changes

- When an original edge and a Boolean intersection overlap, ordinary hover and
  selection now prefer the actual intersection. Right-click candidate cycling
  still exposes the original solid edge.
- Fillet and Chamfer previews, accepted selections and final OCCT calculation
  use the same seed-aware tangent route. Explicitly selecting the original edge
  therefore keeps the original route instead of being silently replaced by an
  intersection.
- Boolean split-edge classification uses the exact length-delimited persisted
  ancestry. A split fragment is an actual joint only when its adjacent faces
  come from at least two distinct source owners; same-owner continuations remain
  original-source edges.
- Existing mixed Fillet and Chamfer routes are canonicalized independently per
  selected route before calculation. This retains multiple intentional routes
  while removing a stale original continuation from an intersection route.

## Compatibility and verification boundary

The correction is shared by the Windows and Linux C++ implementation. Native
document format, geometry precision, side identity, oldest-face ancestry and
container placement are unchanged. Qt remains pinned at 6.11.0 and OCCT at
8.0.1 on both platforms.

Focused native tests cover cross-owner intersections, same-owner continuations,
explicit original-edge treatment, contaminated historical routes, Fillet and
Chamfer. The shared UI contracts cover ordinary and symmetric edge treatments.
`TEST2.prtz` was regenerated read-only without calculation errors, and the user
confirmed in the Windows GUI that default intersection priority, right-click
cycling, preview and final calculation now respect the chosen edge.

No user-visible text was added or changed, so the Czech, English, German,
French and Russian localization catalogs remain unchanged. Native Linux
compilation and execution require their separate host acceptance.
