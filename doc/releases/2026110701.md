# Windows 2026110701 — references, independent launches and interaction corrections

Status: signed Windows release published and publicly verified at
`2026-11-07T18:09:05Z`.

[Download the signed Windows release](https://github.com/ZIMA-Engineering/ZIMA-CAD/releases/tag/ZIMA-CAD-2026110701).

Sketch references selected from Mirror, Pattern and later Boolean results now
retain the exact clicked child identity. Multiple source parents and copied
children remain independent when their geometry changes or display packet order
changes. Moving or rotating the dependent feature Origin reprojects the same
stored child on explicit Regenerate instead of preserving a static snapshot.

This restores two coincident constraints at the intersection of two external
references for the reported 2D Sweep path. The authored `06.prtz` was repaired,
regenerated, saved and reopened through the native implementation; its retained
backup and all other user data are excluded from the release source.

Windows Explorer/document-association launches remain separate ZIMA-CAD
processes. Different files in the same directory may now be open in different
processes, while the same native file remains exclusively reserved. File -> Open
and the integrated File Manager keep their existing same-process behavior.

Visible material faces of half-round and rectangular sheet transitions now map
to their authored history Container for ordinary selection. A click displays
the complete authored preview wire in azure without face fill, and a double-click
in either the View or Tree exposes the transition dimensions. Exact panel/bend
material identities remain unchanged for references and sheet-state operations.
The repair also applies to already cached native geometry without regeneration.

An Up-to Modeling Feature now uses the resolved pending Sketch plane to orient
Side 1 toward the selected target. This includes a pending profile-plane offset,
container frame and changed placement references; a stale committed profile is
not used. Side 2 never reverses the shared Feature direction. When both branches
use Up-to, their targets must classify into opposite Sketch-plane half-spaces.
The dialog rejects a same-side target before mutation and the document core
enforces the same rule for non-GUI callers. An infinite target plane that is not
parallel to the Sketch plane remains directionally ambiguous because the planes
intersect; it does not trigger automatic reversal or same-side rejection.
Deleting a solid that supplies an Up-to target remains an explicit manual repair
case: replace or remove the unavailable target in Properties. The release does
not silently convert it to a cached snapshot or length.

The first ordinary Sketch in a Part opens at the established approximate
monitor-physical scale, whether it is empty, already contains geometry, has been
reopened, or belongs to a placed Body. Its geometry is used only to center the
view. Later Sketches and face-attached Sketches retain their model-context fit.

Ordinary and projected drawing-view placement now renders only foreground
visible/boundary strokes from the already prepared interactive projection. It
does not display hidden, thread, thread-leadin or hatch strokes and does not ask
for precise vector hidden-line preparation. The committed view, Properties,
printing, PDF and vector export keep their complete display settings and exact
geometry. Small Sketch corner-radius handles also outrank an overlapping native
vertex during left-button dragging, while right-button cycling retains access to
both candidates. Dragging the handle back onto its vertex restores an exact zero
radius rather than a floating-point remnant.
