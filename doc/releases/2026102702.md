# Windows 2026102702 — responsive editing and exact native reuse

This Windows release candidate follows `2026102701` with conservative native
workflow, Sketch interaction and View-selection improvements. The semantic
multi-Boolean evaluator remains a measured research probe and is not enabled in
the product.

## User-visible changes

- Auxiliary axis endpoint points are no longer permanent ordinary-View markers
  and the obsolete Axis points toolbar action is removed. A command that can use
  an endpoint reveals and picks the same persisted point through its transient
  context. Parent axes, copied Mirror/Pattern construction, point identity and
  native persistence remain unchanged. Sheet and cylindrical faces remain
  selectable without endpoint markers intercepting ordinary picking. Authored
  points of an active Sketch remain visible independently, including every
  defining point after a segment, circle, arc, ellipse, elliptical arc or
  B-spline changes between profile, auxiliary and construction roles.
- Opening New Feature and assigning Default Origin no longer republishes the
  calculated final-Body scene immediately before its rollback/input scene. On
  the representative Skeleton copy, observed command opening changed from
  1.515 s to 0.280--0.353 s and Default Origin from about 5.116 s to
  0.272--0.280 s.
- Sketch point and dimension dragging reuses the already published calculated
  context. The measured rounded-profile move changed from repeated 90--121 ms
  context reconstruction plus solver/mesh work to approximately 6 ms total in
  the retained interaction path. The lightweight overlay now keeps the complete
  active Sketch wire visible for the whole gesture in ordinary Part and Section
  Sketches. Explicit confirmation still performs the full native solve and
  validation.
- Regular polygons retain an exact centre/radius/phase during interaction.
  Direction-constrained edges scale around the fixed centre when radius is free;
  conflicting locked-radius motion is rejected without changing the document.
- Model rotation, pan and zoom remain available while an explicit geometry
  calculation runs on its worker-owned candidate. Commands, selection, property
  confirmation and document mutation remain blocked until the complete result is
  published.

## Native workflow performance

- An unchanged calculated cache is reused only when operation count, final source
  fingerprint and complete authored-definition digest match. On the protected
  31-operation Skeleton copy, an unchanged save measured 0.587--0.633 s instead
  of 11.558 s. A changed-geometry contract proves that stale reuse is rejected.
- Direct pooled-string loading avoids approximately 410 MB of repeated string
  materialization in the representative cache. The rewritten v2 fixture opened
  in 5.991 s versus 7.43 s before this path; the original v1 source opened in
  7.214 s and remained directly readable.
- Large calculated caches use checksummed Zstandard storage. Existing zlib cache
  envelopes remain readable. This changes disposable calculated storage only;
  authored Part definitions, geometry precision and topology identities are
  unchanged.
- Body activation, visibility and Insert Here metadata revisions share the exact
  immutable calculated packet. Six representative cursor commits changed from
  629--829 ms to 2.2--4.3 ms without OCCT work. Undo/Redo retains the exact state
  that owns each shared packet.
- Fillet/Chamfer same-domain publication validates the actual published shape
  once instead of validating an immediately discarded intermediate and the final
  shape again. Large published shapes use OCCT's complete parallel analyzer;
  calculation precision and validity checks are retained.

The complete measurements, exact-output comparisons and rejected shortcuts are
recorded in the
[performance and redesign gate](../performance/20261027-native-cache-close-and-redesign-gate.md).
An unchanged late Feature OK still measured approximately 47.128 s because the
current evaluator recalculates its expensive dependent history suffix. This
release does not claim that hard calculation target is solved.

## Compatibility and verification boundary

The authored native format version is unchanged. Calculated cache data remains
embedded and disposable; no required sidecar is introduced. Geometry side,
oldest-face ancestry, reference identity, Undo/Redo, protected placement and the
shared Windows/Linux C++ implementation remain intact. Windows and Linux keep the
OCCT 8.0.1 pin; Zstandard is added to both native dependency manifests.

The final focused Windows run passes 14 sequential native/GUI interaction suites,
seven cache/session/save/history/activity suites and six Fillet/Chamfer suites.
The complete native Sketcher contract matrix passes, including polygon direction,
radius, drag, dimension, external-support, Undo/Redo and save/reopen variants.
Czech, English, German, French and Russian catalogs validate; no new user-visible
source text is introduced.

One repeated nested Body/Assembly Sketch GUI process passed seven consecutive
runs and then encountered an intermittent startup access violation. The unchanged
signed `2026102603` executable reproduced the same `0xC0000005` failure on its
fifth repetition, so it is recorded as an existing process-lifetime test limit,
not as a current regression. The pre-existing rounded-tangent-wing native matrix
also retains one rejected driving-height edit while its other 512 angled variants
pass. Neither limitation is claimed fixed.

Native Linux compilation, execution and timing are not established by these
Windows checks. Windows publication acceptance, signed asset digests and trusted
updater discovery will be added only after the committed candidate passes the
release pipeline.
