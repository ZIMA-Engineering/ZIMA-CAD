# Windows 2026111103 — multiple Profile limits and Bend corrections

Status: signed Windows release published and accepted. Native Linux acceptance
remains a separate host gate.

Free **Sheet Profile** width can now use the shared ordered multi-target
**Up To** table. Every route station selects the nearest valid target on its
side. When two planar limits exchange order inside a straight Flat, the Flat
owns the exact broken boundary at that switch instead of one endpoint chord.
Target identities and fallback geometry remain native Profile parameters.

Every generated Profile Bend now exposes its two established end-profile
corrections. A non-master Bend opens a deliberately restricted Properties
window: only its end Sketch is editable. The parent Profile continues to own
the route, placement, start width, radius, angle, thickness, K factor and corner
controls. Each Bend correction is independent, and the following Flat starts
from the corrected physical edge.

Ordinary feature selection also resolves a generated Flat or Bend's authored
Sketch wire back to its logical Profile owner, while preserving the attached
first-Bend exception. The public README now begins with ZIMA-CAD's parametric
CAD philosophy supplied by the project author.

Thirteen focused Windows native and real-GUI contracts pass: Sheet Profile,
Profile, Flat and Bend creation/editing; multi-target Feature parameters; Bend
attachments and arc-only interaction; Sketch dimension and relation commands;
and all five localization catalogs. The matrix includes exact planar target
switching, real target-table interaction and inspection, independent successive
Bend corrections, following-Flat regeneration, stable identities, invalid-edit
rejection, Undo/Redo and native save/reopen. See the
[focused verification record](../verification/20261111-sheet-profile-multiple-targets-and-bend-corrections.md).

Exact circle, ellipse, spline and mixed analytic target boundaries remain a
separate extension. Curved finite targets continue to use their persisted exact
ray geometry at generated span stations; display tessellation is not promoted
to authored geometry. No native document format, calculation tolerance,
protected shared placement behavior, geometry-side meaning, Qt 6.11.0 or OCCT
8.0.1 pin changed. A complete repository-wide test run and native Linux
execution are not claimed by this Windows release.
