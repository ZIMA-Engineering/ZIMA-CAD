# Windows 2026103101 — final-first history publication

This Windows release follows `2026102803` with a focused history-editing change.
The complete final Body is published before nonessential intermediate viewer and
persistence packets, while the native OCCT topology chain still evaluates every
required operation in authored order.

## Changes

- Editing an existing history Feature prioritizes the complete final visible
  result and defers large intermediate packets that no calculation dependency
  consumes.
- Exact preceding boundaries remain available for Sketch body-edge projection,
  local intersections and Drill Point. Fillet and Chamfer owner packets remain
  complete.
- Properties materializes a deferred real rollback body on demand. Remaining
  disposable boundaries complete at low priority from private snapshots without
  republishing the unchanged final scene.
- Cache-only boundary publication preserves the active `PartDocument` object,
  editor pointers, document revision and Undo/Redo stacks.
- Opening an existing Feature's Properties preserves the current camera instead
  of fitting or recentring the rollback scene.
- Existing **Origin axis** and **Centroid axis** controls now sit with **Text**,
  separated from **Symmetric**, **Direction** and **Swap sides**. No new modeling
  option or persisted field is introduced.

## Representative Skeleton measurements

All protected-data checks used isolated copies of
`ZE0176-0101-0000_SKELETON.prtz`; the original project file was not modified or
packaged. The final automated Windows Release scenario measured:

| Interaction | First edit | Repeated edit |
| --- | ---: | ---: |
| Open Properties | 1.379 s | 1.860 s |
| Draft value update | 0.061 s | 0.067 s |
| Changed OK | 31.437 s | 25.181 s |

Undo measured 0.515 seconds, Redo 0.568 seconds and Save 24.546 seconds. The
repeated early edit is faster, but this release does not claim the desired
approximately three-second early-history confirmation. Required OCCT topology,
Boolean and reference-settling work remains in the foreground.

A diagnostic simplified Skeleton copy reduced complete calculation from about
28.9 to 16.93 seconds, early editing from 40.7 to 12.41 seconds and last-feature
creation from 5.23 to 1.447 seconds. It demonstrates the cost of authored rounded,
Thin and edge-treated geometry; it is not a replacement model. A 0.01 tolerance,
removing history cache and synchronously prewarming rollback were measured and
rejected. Geometry precision is unchanged.

## Compatibility and verification boundary

The implementation is shared by Windows and Linux C++. Native document format,
geometry precision, stable references, side identity, oldest-face ancestry,
Undo/Redo and protected container placement are unchanged. Qt remains pinned at
6.11.0 and OCCT at 8.0.1 on both platforms. No user-visible string or localization
key changed; the Czech, English, German, French and Russian catalog contract
passes.

Focused Windows Release checks pass for model calculation and rollback
materialization, metadata, Feature layout, Solid State, multi-Body history,
history cache and recovery, external Sketch dependencies, derived copies, Thin,
Fillet/Chamfer, Shell, Drill Point, workspace activity, document transactions and
the complete native Skeleton GUI scenario with camera retention, repeated edits,
Undo/Redo and save/reopen.

The finite record documents three unrelated baseline gaps: a stale expected
Linux runtime fingerprint, an older active-Sketch construction-point image
assertion and an imported-body signed work-plane fixture. Native Linux compilation,
execution and timing require their separate host acceptance.

Detailed measurements and rejected experiments are recorded in
[`20261031-final-first-history-publication.md`](../performance/20261031-final-first-history-publication.md).
