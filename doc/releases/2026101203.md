# Windows 2026101203 — native File Manager

## Changes

ZIMA-CAD adds a native File Manager as an ordinary top-level application tab.
Multiple File Manager tabs keep independent navigation state. The navigation
row starts with Home and includes Back, Forward, Up, an editable path, a name
filter and a direct File Manager settings link. File > Open now opens this tab.

The left side presents the working directory first and configurable data sources
as separate expandable source pages with their own directory trees. Factory
sources cover formats, materials, symbols, templates, sheet-metal content, the
new native-library location and the future engineering-table library. Global
Settings controls source order, paths, enabled/read-only state, company branding,
the default view, thumbnail size and hidden files. Its wider minimum size keeps
the localized tab strip visible.

The Project, Overview and Files views replace hand-authored project HTML with a
click-based workflow. Project metadata and images are editable through the
shared in-application properties window. Overview builds thumbnail tiles
automatically. Files provides checkboxes, name and native-type filters, Copy,
Move and Delete, and metadata/native parameter columns.

`0000-index/metadata.ini` version 3 identifies projects with
`Directory/Kind=project`. Native Part and Assembly documents remain authoritative
for their parameters. The File Manager reads them without OCCT calculation,
edits them through the shared workspace transaction or native closed-document
save path, and mirrors the values with `Provider=zima-cad` for other systems.
Browsing legacy version 2 metadata is read-only; the first native parameter edit
in a writable directory creates the version 3 interoperability mirror. Family
Table editing and ZIMA-Parts migration remain separate follow-up work.

`config/lib/02-NATIVE` and `config/lib/03-ENGINEERING-TABLES` establish reviewed
locations without copying any production engineering-table data or legacy
Pro/ENGINEER documents. New File Manager, Copy and Move icons use the existing
resource/icon system. All user-visible additions are translated in Czech,
English, German, French and Russian.

## Verification status

The synthetic File Manager test passes source navigation, project detection,
Overview and Files content, version 3 metadata, native-provider routing,
creation of version 3 metadata on the first native edit and independent state
in multiple tabs. It uses only temporary generated directories.

The integrated Windows GUI test passes File > Open, multiple tabs, exclusive
switching between CAD, File Manager and the web browser, direct editing of a
real saved native Part parameter, its metadata mirror, tab closure and process
shutdown while a File Manager tab remains open. The shutdown case caught and
verified a Windows heap-corruption repair: Qt now destroys filesystem-model
pages with their owning central-widget subtree.

The portable-settings and application-lifecycle contracts pass. The
five-language source coverage and translation contracts pass. The product and
standalone File Manager targets build with the shared Windows C++/Qt sources.
No native document schema, geometry algorithm, container-placement contract or
OCCT version changed.

The existing browser widget rendered its green/purple native fixture correctly,
but the current automated whole-window capture returned the Windows desktop in
two attempts instead of the application window. This is recorded as a desktop
capture limitation; the new integrated test independently verifies that browser
and File Manager surfaces switch exclusively. Packaged acceptance remains to be
recorded below. Linux build and desktop verification remain pending on the Linux
host.
