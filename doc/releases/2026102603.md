# Windows 2026102603 — faster native workflow and Sketcher refinements

This Windows release candidate continues the exact-output Skeleton work and
includes the associated modeling and interaction corrections developed after
`2026102602`.

## User-visible changes

- Creating a Sketch dimension can immediately open its existing inline value
  editor. The behavior is enabled by default and can be disabled globally in
  Options. Direct, universal and corner-radius dimensions share the behavior.
- Numeric fields accept mixed unit expressions such as `11 mm + 1`, `1 in +
  5 mm` and the `inch` alias while retaining the document's established unit
  conversion and validation.
- New modeling features use localized two-digit sequence names (`01`, `02`,
  ...), including Flat, Bend, Pattern and Mirror, while avoiding collisions with
  names already present in the document.
- A rectangle started on one of two parallel external references and completed
  on the other can infer symmetry about the perpendicular Sketch axis. The two
  reference contacts remain independent and editable.
- Sketch Point uses a white solid-point icon. Reference and Intersection use
  brown linework and solid points; their contour variants remain visually
  distinct.
- Sheet from Body aligns the first Flat origin with one or both applicable Part
  Origin symmetry planes when those planes cross the selected source face. The
  generated panel remains geometrically identical and does not add a required
  associative constraint.
- Assembly STEP and IGES export excludes Skeleton components by default. The
  export options window offers an explicit **Include Skeleton** checkbox.

The earlier `2026102602` Flat-to-Flat placement, sheet/cylindrical-face
selection and parent-driven Mirror/Pattern construction-axis corrections remain
covered by their focused contracts.

## Native workflow performance

- Unchanged history prefixes and resolved local references are reused only when
  their complete inputs and dependency fingerprints still match.
- The persisted calculated cache can store the final self-contained Body packet
  once and reconstruct exact history boundaries without invoking OCCT. Layouts
  that cannot prove this mapping retain the complete boundary-array encoding.
- Cache references expand in place, avoiding redundant moves of approximately
  1.5 million ordinary JSON nodes in the representative Skeleton.
- OCCT Boolean parallelism is enabled adaptively for sufficiently complex input
  rather than imposing its overhead on small operations.
- Properties preparation, Tree refresh, final packet transfer and several
  repeated reference/kernel preparation paths avoid work whose inputs have not
  changed.

On the reported 51,025,383-byte Skeleton copy, accepted Windows Release samples
observed 18.206--18.464 s to open the previous cache, 15.975--16.237 s to save,
and 13.204--13.579 s to reopen the rewritten cache. The warm final-Feature edit
retains a 25-of-26 history prefix and was measured at approximately 4.6 s; this
is materially faster but is not represented as the requested one-second target.
Timings are machine- and cache-state-dependent. Exact definitions and every
expanded calculated packet match before and after the round trip.

No geometry precision, authored model content, topology identity, reference
side, Undo/Redo or container-placement contract was weakened. The compact form
is an optional disposable calculated-cache encoding inside the existing native
document, not a new required authored-data version or an external sidecar.
Existing current-format documents open directly; resaving them activates the
new cache path.

## Verification boundary

Focused Windows native and GUI contracts cover the cache encodings and malformed
input rejection, exact multi-Body/suppression/Boolean round trips, Mirror/Scale
persistence, two successive dimension edits and drags, midpoint and external
reference cases, unit expressions, automatic dimension entry, sheet conversion,
export filtering, feature naming, axes and selection behavior. Czech, English,
German, French and Russian catalogs are validated.

The shared Windows/Linux C++ implementation and OCCT 8.0.1 pin remain aligned.
Native Linux compilation, execution and timing are not established by the
Windows checks. Windows publication acceptance, signed asset digests and updater
discovery will be recorded here only after the release is published and verified.
