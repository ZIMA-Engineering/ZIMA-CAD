# Windows 2026111301 — Robust ZIMA edge-treatment terminals and recovery

Status: signed Windows release published and accepted. Native Linux acceptance
remains a separate host gate.

This release completes the current ZIMA Fillet and Chamfer correction cycle.
Terminal construction now derives its limit from the actual neighbouring
surfaces and material domain instead of retaining an arbitrary extended sweep.
The resulting treatment is trimmed at planar and curved ends, including
non-orthogonal corners and cases where a following radius is larger than a
preceding radius. Two-route nodes keep the authored branches without an
invented connector. Invalid candidate pieces are discarded instead of leaving
teeth, tongues or protruding treatment geometry. Chamfer uses the same terminal
principles where they apply.

The lightweight azure Fillet preview follows the corrected terminal route for
the reported straight and spline-supported cases. The general line–cubic
B-spline–line route no longer undergoes an invalid periodic reshaping step, and
its material-side classification uses the real route midpoint. This corrects
the reported `READIUS2.prtz` path while preserving the valid pre-cleanup result.

ZIMA-owned Fillet and Chamfer result fragments now publish stable owned edge
and vertex identities. Their resulting edges and endpoints can therefore be
used by dependent operations without borrowing identity from the preceding
body. When an upstream Fillet becomes invalid, editing a dependent invalid
Fillet uses the retained last-valid rollback input and no longer crashes. The
failed dependency remains visible for repair; it is not treated as valid.

The shared container Origin entry remains unchanged except for the approved
one-shot interaction correction: after an Origin reference is selected, its
button releases automatically so the next placement reference can be picked.
No native document format, placement-solving rule, calculation tolerance, Qt
6.11.0 or OCCT 8.0.1 dependency changed. No user-visible text was added or
changed, so the Czech, English, German, French and Russian catalogs require no
new entries. The implementation remains shared C++ for Windows and Linux.

## Focused verification

The following nine focused native, GUI and localization contracts passed:

- `zima_cpp_solid_state_fillet_document_tests`
- `zima_cpp_occt_planar_edge_fillet_tests`
- `zima_cpp_occt_planar_edge_chamfer_tests`
- `zima_cpp_body_preview_ui_contract`
- `zima_cpp_invalid_dependent_fillet_ui_contract`
- `zima_cpp_translations_contract`
- `zima_cpp_model_calculation_tests`
- `zima_cpp_thin_feature_wire_tests`
- `zima_cpp_boolean_split_edge_tests`

Clean CLI regeneration of the supplied `RADIUS.prtz` and `READIUS2.prtz`
examples completed successfully. The tests cover terminal trimming, larger
successive radii, spline-supported routes, the analogous Chamfer path, stable
owned edge/vertex references, invalid dependency recovery, preview geometry
and the one-shot Origin control. They do not claim every possible high-valence
or curved corner solution.

The broader repository run was not accepted as globally green. The focused
scope passed, while the broad attempt also exposed unrelated existing or host
issues: a portable-settings factory-source mismatch, a browser test with no
result, and a QtWebEngine GLES failure/hang in the file-manager test. Native
Linux compilation and execution were not run on this Windows host.
