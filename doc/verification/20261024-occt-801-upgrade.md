# OCCT 8.0.1 transition — 2026-10-24

## Local Windows outcome

The complete Windows application/test and Debug/Release SDK builds succeed.
The broad run completes **317 tests: 275 pass and 42 fail**. All 42 failures
reproduce with the same diagnostics on the current implementation built against
OCCT 8.0.0. No newly introduced failure is observed in this finite matrix.
The 42 existing defects or outdated fixtures remain unresolved; this is not a
green full suite or universal geometry acceptance.

See the [exact results and runtime hashes](20261024-occt-801-upgrade.json).
Selected GUI scenarios pass on 8.0.1, and all three representative timing cases
pass on both kernels. Candidate/signed Windows package acceptance now passes;
native Linux execution remains a separate host gate.

## Scope and acceptance

The user authorized attempting the shared OCCT 8.0.0 to 8.0.1 upgrade and
verifying ZIMA-CAD functionality. Loft is a subsequent feature, not part of
this change. No native document format or protected container placement
contract change is intended for this kernel upgrade. Preserve the existing
development launcher, private models and library edits. Following the user's
subsequent instruction, publish a signed Windows release only after the upgrade
passes its verification gates.

Windows and Linux dependency recipes must select the same source release and
the same Gauss integration patch. Native Linux compilation, GUI and packaging
acceptance must run on a Linux host; this Windows investigation cannot establish
them. Do not infer unchanged behavior from compilation or successful reopening
of cached geometry alone.

## Local evidence

Disposable sources, SDK, logs and test inventories are under
`build/occt-801-audit/`. The existing SDK and development BAT remain unchanged
while the candidate is investigated. Some registered baseline tests have no
compiled executable; these are not passing evidence. The initial Gauss test
attempt was not run because its baseline executable was absent. Compile the
required targets before candidate acceptance and record baseline limitations.

An initial sandboxed compiler probe did not complete. The isolated SDK build
was restarted through the approved native compiler execution path.

The unchanged Gauss regression was compiled separately against the existing
8.0.0 SDK and passed all seven analytical cases: 1,952/1,953/1,972 intervals
on both surface knots and boundary curves, plus a 66-interval extended-bound
case. Checks cover area, volume, centroids and inertia tensors at the test's
existing tolerances. Evidence: `baseline-gauss-rebuilt.log`.

The same seven cases also pass against the isolated 8.0.1 SDK, using the same
test source and unchanged tolerances. Evidence: `candidate-gauss.log`.

An isolated CLI runtime contains hash-verified 8.0.1 DLLs rather than the
baseline vcpkg app-local copies. It passes native Part creation from the start
template, a calculated symmetric extrusion, save/reopen and independently
expected volume 6,000 mm3. New Assembly template/save/reopen and Drawing PDF/JPEG
export also pass. Evidence: `early-cli.log`, `early-cli.json` (DLL SHA-256 values).

All 13 isolated-runtime GUI scenarios pass: native new-document templates in
mm/in, ordered multi-face Up To, Feature side reversal, curve-plane points,
rounded Sketch Mirror, symmetric rectangle, Sketch dimension entry, original
Sketch preview wire and four factory FORM selection cases (BridgeLance,
CornerGusset90, DimpledHole and VentilationWindow). Exact scenario names,
durations and exit codes are in `early-gui.json`; individual output logs are
`early-gui-*.log`. These run during concurrent compilation and are correctness
checks, not performance comparisons. They do not establish all possible FORM
insertion/editing cases or resolve the separate baseline GUI assertions.

The fresh all-target build exposed MSVC C1128 in `cli_process_tests.cpp`:
the test exceeded the standard COFF section count. A target-local `/bigobj`
option repairs this Windows test-build issue, matching the project's existing
approach for large sources; no product modeling code is changed. Evidence:
`product-build-first.log`; the build is resumed after this fix.

The complete application/test build then succeeds. The broad selection contains
316 named tests; CTest adds a required setup case for 317 executions. The final
Windows port DLLs are copied only after deployment finishes and their SHA-256
values are verified against `port-sdk-proof.json` before the run. The broad run
finishes in 1,904 seconds with the results stated above.

The broad run exposed existing failures beyond the initial 25-test sample.
For differential checks, the current SDK-facing kernel/interchange sources and
test sources are compiled against the preserved 8.0.0 SDK. Twenty fresh current
SDK-independent product libraries are reused; a source scan finds no OCCT
includes outside the kernel/interchange modules. The temporary comparison build
uses the same source directories via junctions, not alternate modeling
implementations. Its local CMake gate selects 8.0.0 solely for this comparison;
the tracked product gate and both platform recipes remain pinned to 8.0.1.

All ten failing Solid State continuation cases also fail with the same reported
reasons on this fresh 8.0.0 boundary; four positive controls pass on both.
Evidence: `fresh-baseline-solid-state.log/.xml`. A subsequent 33-case failing
selection also fails on the fresh baseline (`fresh-baseline-failed.log/.xml`).
The remaining nine failures reproduce in `fresh-baseline-failed-2.log/.xml`.
Generated 32-hex IDs in two diagnostics use encounter-ordered placeholders for
comparison, preserving equality relationships; geometry values and side choices
are unchanged. One layout test initially stops at a different hover assertion
during concurrent GUI activity; an isolated rerun reaches the same point-color
failure as 8.0.0. All 42 failures remain open.

Two pre-existing GUI harness assumptions are updated without changing dialogs:
Family Table now checks the current consecutive full-width source/name rows,
and the curved Revolution Up To scenario clicks the shared reference table
instead of searching for the retired visible line edit. Both corrected
scenarios pass after relinking (`gui-corrected.log/.xml`). Catalog verification passes
for cs/en/de/fr/ru; no ordinary user-visible strings are changed.

The existing 8.0.0 development binaries pass 21 of 25 selected registered
regressions in 678.95 seconds. Four baseline failures must not be attributed
to the new kernel without comparison:

- Rounded Sketch Mirror: 180-second timeout.
- Boolean split edges: six geometry cases and repeated ancestry checks pass,
  then a new Assembly rejects the available document format.
- Family Table GUI: main view source/name top-row assertion.
- Common surface GUI: the later curved Revolution case searches for a retired
  visible target field instead of the current reference table.

These are the existing development executables, not a fresh full rebuild of
8.0.0. Their timestamps/source currency must be considered when interpreting
comparisons. Evidence: `baseline.log`, `baseline.xml`,
`baseline-selected.txt` (exact 25-test matrix).

`TopTools_FormatVersion_CURRENT` remains `VERSION_3` in both kernels. This
source check does not establish complete persistence compatibility; native
save/reopen and dependent-operation cases are recorded in the broad matrix.

The user subsequently authorized documentation, commit/push and a signed
Windows publication after successful verification, followed by Loft restricted

are authorized for that subsequent work only with affected factory libraries
