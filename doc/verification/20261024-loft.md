# Loft finite verification — 2026-10-24

This record covers the shared native C++ Loft implementation after the immutable
OCCT 8.0.1 Windows release 2026102401. That public package does not contain Loft.
The [machine-readable receipt](20261024-loft.json) records selected results and
local evidence hashes. It is not an exhaustive system or Sketcher acceptance.

## Implementation and persistence

Loft owns only planar 2D Sketch definitions, with independent parent-local
placement. Profile and guide order use stable owned feature IDs. The upper and
lower lists reuse common reference-cell appearance, ordering controls and eyes;
owned object fields open editors rather than arm external reference entry.
The existing complete General Surface owned-Sketch Properties/Sketcher lifecycle
is shared through an adapter; its Curve3D branch is not exposed by Loft.

The new Loft-only record stores complete owned definitions, identities, placement,
constraints and locks. Existing required feature records, INI/JSON versions,
start templates, factory definitions and extensions are unchanged. There are no
legacy Loft paths or required sidecars. Every one of the 1,185 tracked native
factory documents loads with the current CLI reader (76.03 seconds in this run).
Library extensions use byte-identical temporary .prtz copies for dispatch;
original factory and user-authored library files are not overwritten.

Actual GUI creation of a new Part and Assembly from start templates passes. The
Part's first editable Body and normal modeling commands are active; the Assembly
has its normal component commands. Drawing/template editing, region priority,
shared confirmation, persistence and five UI languages also pass separately.
No existing library geometry contract requires conversion for the additive record.

## Explicit limits

Inputs currently require one contour without holes. Guided construction requires
at least two guide Sketches. Exact Gordon output must meet the requested contact,
reparameterization, profile and guide tolerance; some rational networks are
rejected despite OCCT Done. No sampled fallback or precision reduction is used.

The focused tests do not exhaust arbitrary arcs/B-splines, nonparallel network
planes, Loft-specific Family variant GUI flows, nested Assembly occurrences,
dependent Boolean chains, or every Sketcher dimension/drag state. The solver is
unchanged; owned editor entry/return and repeated native geometry edits do not
establish a full driving/reference, locked/unlocked, under/fully constrained,
selection-order and drag matrix. Those variants remain explicitly unverified.
Native Linux compilation/execution requires its host. The implementation and
OCCT dependency pins remain shared between Windows and Linux.
