# Line Bend, RIP and Sheet-from-Body detachment verification

## Scope

This change adds one shared C++ implementation of Line Bend for Windows and
Linux. A Line Bend owns one ordinary Sketch with exactly one finite straight
segment. The selected fixed side remains stationary and the other material
region rotates about that segment. Properties expose the inside radius, bend
angle, fixed side, reverse direction and the existing sheet-thickness and
K-factor override conventions. Creation and later editing use the same internal
Properties window and owned-Sketch workflow.

Sheet from Body now accepts a planar starting face, additional planar or
cylindrical included faces and ordinary Sketches used as RIP definitions. The
dialog initially offers twelve face rows and three RIP rows and appends another
row when the last one is populated. An empty included-face list converts the
complete connected sheet branch. RIP consumes open or closed ordinary Sketch
geometry as a topological separation without removing material. Generated Flat
and Bend children retain explicit bindings to their source surfaces and radii.

The Sheet-from-Body Tree item offers **Explode all**. A still-bound generated
Flat or Bend offers **Explode part**. Partial detachment preserves the selected
child as an independent native feature. Full detachment freezes the generated
children at their current numeric frames, removes the conversion owner and, for
a same-Body conversion, suppresses the replaced source-material prefix. A
second request is a no-op and creates no Undo transaction or calculation.

## Native format and factory data

The approved Part INI format changes from 51 to 52 and the internal authored
packet version changes from 75 to 76. The strict boundary records Line Bend,
RIP inputs and generated-child detachment without a legacy execution path.
Repository-owned Part, FORM, frame, title-block, symbol and Part test assets
were migrated in an isolated directory. Format-51 calculated packets were not
carried across the boundary.

The current OCCT 8.0.1 implementation recalculated, saved and reopened 1,058
repository-owned native Part-based assets: 5,477 history boundaries completed
with zero calculation errors and exact native readback. An independent cache
comparison covered 1,042 calculated assets and preserved their original
reference packets, side/reference identities and available volume and surface
area values. The four Part/Skeleton start templates were regenerated by the
same writer; Assembly templates retain their unchanged Assembly format.

No private project, custom library or `config/config.ini` file participated in
the conversion.

## Finite regression results

The final Windows modeling run passed 12 of 12 selected native and GUI
contracts in 176.01 seconds:

- Line Bend Properties, creation, preview, edit, inline dimensions, Cancel,
  Undo/Redo and native reopen;
- Sheet-from-Body conversion, same-Body use, included faces, RIP, generated
  bindings, partial/full detachment and cold regeneration;
- ordinary Bend continuation, history deletion and history-fingerprint cache
  invalidation;
- Part-format creation, native metadata inspection and Unicode save/reopen;
- feature unit input and all Czech, English, German, French and Russian catalog
  entries.

Two additional five-language New Document GUI contracts passed in 87.15
seconds. They created millimetre and inch Parts, sheet Parts, Skeletons and
Assemblies from the committed templates, confirmed the active editable Body or
component context, checked normal command availability, saved and reopened the
documents, and retained the established Drawing defaults. The complete selected
result is therefore 14 of 14 passing contracts.

The initial format run exposed two stale test expectations: the independent
metadata reader still admitted format 51, and a converted parity fixture kept
its old definition fingerprint. Both expectations were updated to the approved
strict format and the complete selected run then passed.

## Limits

This is finite Windows verification, not a claim that every repository test was
run. Native Linux compilation, GUI execution and packaging remain a separate
Linux-host gate. The shared C++ algorithms, Qt 6.11.0 and OCCT 8.0.1 pins are
unchanged across platforms. Protected shared container placement and geometry
side identity were not modified.
