# Wrap sketch and Wrap relief

Status: verified in the Windows development runtime; portable publication is a
separate gate. Baseline: `ab2ed163340a37f6a89118564fb1ac3904be6b64`.

## Implementation

The existing Feature Properties dialog offers Wrap sketch and Wrap relief.
Its type menu opens downward. Both consume the existing placed Feature Origin,
owned planar Sketch, reference-entry controls, rollback and OK/Cancel lifecycle.
Wrap sketch supports curves, closed surface regions and embedded artwork.
Wrap relief uses Add/Subtract and a positive normal Correction. There is no
Unwrap command and no automatic conversion of image pixels into relief.

Cylinders preserve circumferential arc length and axial distance. Cones use
sector development. Spheres use the exponential map: distances from the anchor
are geodesic lengths and transverse scale is `sin(rho/R)/(rho/R)`. The user
accepted that spherical distortion. The formulas and primary sources are in
[the design record](../FEATURE_WRAPPING_PLAN.md).

Native curves retain authored curve/point ancestry. Noncylindrical curves use
tolerance-controlled OCCT approximation and projection, followed by independent
checks against the analytic map. The sphere support is reparameterized at the
anchor so an arbitrary native UV pole does not invalidate an ordinary region.
The actual bounded face, including holes, remains the target. Exact edge and
region containment checks use nondestructive Boolean operations.

Images retain their embedded bytes, opacity and source coordinates. Curved
triangles and UV coordinates are persisted in the native viewer packet. The
viewer caches textures and depth-tests them against the model. Later native
cuts clip artwork to surviving target descendants using explicit ancestry.
Body and Assembly scene aggregation retains the image packet.

Only the new Feature discriminator/payload and optional curved-image packet
extend persistence; existing documents do not receive a version-field rewrite
or a legacy adapter. Required data remains in the native document.

## Finite Windows verification

Runtime: MSVC Release, Qt 6.11.0, OCCT 8.0.1.

- Analytic equations: cylinder signed lengths and inverse coordinates;
  cone isometry across half-angles `1e-7`, `0.05`, `0.35`, `1.3` radians;
  sphere radii `0.05`, `1`, `37`, `1000`, geodesic distances, Jacobian,
  inverse coordinates and oblique frames. Both direction flags, normal offsets,
  changed native seams and singular/overlapping image domains are covered.
- Native geometry: 24 base combinations of cylinder/cone/sphere, curves/surface/
  relief, both directions/material sides, including spherical polar anchors.
  Closed regions with circular holes, open curves, image-only definitions,
  repeated cached evaluation, changed direction and downstream slot cuts pass.
  Checks include valid B-Rep, material volume, source ancestry and actual image
  vertices outside the cut. The matrix takes about four seconds on this host;
  this is a synthetic observation, not a general performance guarantee.
- GUI: actual bounded-face picking, clearing, replacement, independent eye,
  analytic wire preview, curved artwork pixels, native save/reopen, unchanged OK,
  Cancel, Undo/Redo, whole-Origin placement and reopened placement pass.
  Picking/preview and unchanged OK perform zero body calculations. Repainting
  does not upload the texture again. Language/theme changes retain authored data.
  Tree and View single-click selection share the authored wire and synchronize
  the selected feature. Double-click inspection does not calculate geometry,
  open Properties or change the document revision.
- Source lifecycle: three successive source-size changes preserve curve ancestry;
  restoring the source restores material volume. Family suppression/reactivation
  removes/restores artwork and material. Missing targets reject calculation
  without moving the retained frame, and replacing the target repairs the result.
- Both Feature labels, correction and direction controls pass all five UI
  languages and both themes. The complete translation coverage contract passes.
- Seven dependent native suites pass: derived-copy contracts and commands,
  Assembly contracts, placement commands, Projection history and documents,
  and Wrapping history. Feature persistence and analytic map executables pass
  separately. The complete Feature-type UI contract passes, including existing
  Projection and ordered-limit controls. Its correction-label lookup was updated
  to inspect the established composite row instead of the obsolete direct field.
  Distribution unit tests pass: 32 tests, two existing skips.
- The complete FEM GUI suite passes after the viewer changes, including actual
  MP4 export/decode, activation visibility, thermal/mechanical analyses and
  five languages/two themes. See [FEM verification](20261124-fem-player-and-video.md).
- All six Part/Skeleton/Assembly start templates were regenerated and reopened
  by the changed native implementation. Their bytes remain unchanged. The GUI
  new-document contract confirms active editing context and normal commands.
- All 1,190 tracked factory native assets load with the changed CLI. All 1,074
  pre-change Part/Assembly/library fixtures retain their inventory hashes;
  none contains a pre-existing Wrapping definition requiring conversion.
- The current user `50.prtz` regenerates on a separate copy. All 172 protected
  Toyota files retain their original hashes. The ten native Toyota copies have
  the same supported-format status as release 2026112403: two Drawings load;
  seven Parts and one Assembly use previously unsupported formats. No migration
  adapter or rewrite of these protected originals was introduced.

Development logs and screenshots are retained under `build/fem-20261124`.
They are disposable evidence, not document dependencies or release source.

## Limits and pending release gates

This is a finite matrix, not exhaustive geometry coverage. Cone apices, the
spherical antipode, invalid offset radii, self-overlapping image domains and
unconstructible regions are rejected; tolerances are not relaxed to accept them.
Image pixels remain artwork rather than exact editable curves. Native Linux
execution is unverified. External Skeleton targets and nested Assembly artwork
have not yet received a dedicated interactive matrix. No Sketcher constraint
solver or dragging behavior was changed by this work.

The portable runtime must repeat the Wrap and FEM GUI checks, including video
encoding without the development SDK on PATH. Committed-source, dependency,
factory, archive, signature and publication gates remain required.
