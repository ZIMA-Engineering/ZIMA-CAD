## Lifecycle and ownership

Changed multi-target limits and corrected Revolutions use the same native
primitive, clipping, retained-patch and correction algorithms as acceptance. A
private operation is evaluated without replaying downstream history. Preview
retains the operation's own non-seam wire, without applying its final Body Boolean
or calculating unused aggregate properties.

The command owns immutable inputs, one worker and a 150 ms debounce. Different
pending definitions clear the old wire. A completed result publishes only for
the current request and source generation. A failed request is terminal until
the input changes; closing the command prevents later UI publication.

Opening unchanged Properties must reuse the stored operand wire without a kernel
call. A missing or failed stored wire reports its unavailability until an input
changes. The initial callback is installed after the dialog owner and rollback
context, so a cached synchronous result is not discarded during setup. Inspection
reads the existing viewer packet. Preview never creates a document transaction.

## Assembly Through-all input

Assembly cutting previously evaluated a standalone Through-all tool without its
selected component bounds, using the kernel's large empty-input fallback. A draft
bounded by actual components would disagree with that accepted original wire.
The new shared native Feature tool path receives the same selected pre-cut native
components for both the exact draft and accepted cutter. Ordinary Part history
and Assembly features without Through-all retain their existing calculation path.

Each selected source is wrapped in a lightweight immutable compound with its
component placement. No display triangulation is copied or substituted for native
geometry. Fingerprints include selected identities, source fingerprints and rigid
placements. Inactive retained Up To fields do not introduce source dependencies.
Empty/suppressed source sets retain the ordinary no-input behavior.
